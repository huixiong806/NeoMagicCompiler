## 1. 游戏是什么

**Neo Magic Compiler** 是一款编译原理教学游戏。玩家扮演两名探索者，在一座即将失稳的地下遗迹中
逐层深入，从"星之语（汇编）"一路学到"亲手写出一个编译器"，最终用自己写的编译器跑通封印程序。

教学主线四章：

| 章 | 标题 | 教学 | 玩家写什么 |
|----|------|------|-----------|
| 一 | 魔法就是计算 | 星之语（RV32 汇编）：寄存器、指令、内存、分支、循环、函数调用 | 汇编指令序列 |
| 二 | 逐渐抽象的魔法 | 星咒（C 子集）：变量、算术、分支、循环、数组、指针、函数、递归、结构体 | C 函数 |
| 三 | 简单的魔法翻译机 | 输入解析：词法扫描、状态机、运算符优先级、求值 | 一个"咒文解析机"（读字符流 → 求值 → 输出） |
| 四 | 魔导符的编织 | 编译原理：词法分析 → 语法分析（AST）→ 语义检查 → 目标代码生成 | 一个把星咒编译成星之语的编译器 |

第五章（IR、寄存器分配、优化、SIMD）不在本次交付范围，但架构上预留（见 §9）。

## 2. 运行时架构（最终形态）

全部执行逻辑收进 **三个纯 Rust crate**，Tauri 只做进程边界与 IPC 适配。

```
┌──────────────────────────────────────────────────────────────┐
│ 表示层  compiler-content/frontend  (TypeScript + Lit + Vite) │
│   editor / toolbar / machine-state panel / console           │
└───────────────────────────┬──────────────────────────────────┘
                            │ Tauri IPC (invoke)
┌───────────────────────────▼──────────────────────────────────┐
│ 应用层  app/src-tauri  (Tauri 2)                             │
│   命令注册、会话状态、资源定位                                │
└───────────────────────────┬──────────────────────────────────┘
                            │ Rust 函数调用（同进程，零协议开销）
┌───────────────────────────▼──────────────────────────────────┐
│ 领域层  crates/neomagic-core                                 │
│   关卡加载 · 运行器 · 判定器 · Judge 注册表 · 存档（serde）    │
└───────┬──────────────────────────┬───────────────────────────┘
        │                          │
┌───────▼────────────┐  ┌──────────▼─────────────────────────┐
│ crates/starlang    │  │ crates/riscv-assembler             │
│  星咒(C 子集)编译器 │  │  星之语汇编器                       │
│  lexer/parser/type │  │  两遍扫描 · 伪指令 · 数据段         │
│  /codegen/runtime  │  │  · 白名单校验                      │
└───────┬────────────┘  └──────────┬─────────────────────────┘
        │  产出的星之语源码         │  产出的机器码
        └──────────────┬───────────┘
┌──────────────────────▼───────────────────────────────────────┐
│ 执行层  crates/riscv-simulator                                │
│   RV32IM 取指/解码/执行 · RAM+MMIO · 暂停条件 · 历史回溯       │
└──────────────────────────────────────────────────────────────┘
```

**为什么不再有独立进程的 Assembler / Judge**：它们是纯函数（文本 → 机器码、状态 → 判定结论），
放进进程内可获得编译期类型安全、可单元测试、无 spawn 开销。这同时也让"关卡自检"（用参考解跑
全部测例）能作为 `cargo test` 的一部分离线执行。

**为什么汇编器与 C 编译器分成两个 crate**：星咒编译器把星咒编译成**星之语源码**（文本，可在控制台
展示给玩家，教学价值高），再由汇编器汇编成机器码。两者职责单一、可独立测试。

## 3. 目标机器：魔导引擎 ISA（星之印）

### 3.1 指令集

标准 **RV32IM** 子集，全部 32 位定长指令，小端序，指令与数据同址。

| 类别 | 指令 |
|------|------|
| R 型运算 | `add` `sub` `sll` `slt` `sltu` `xor` `srl` `sra` `or` `and` |
| R 型乘除 | `mul` `div` `divu` `rem` `remu` |
| I 型运算 | `addi` `slti` `sltiu` `xori` `ori` `andi` `slli` `srli` `srai` |
| 加载 | `lb` `lh` `lw` `lbu` `lhu` |
| 存储 | `sb` `sh` `sw` |
| 分支 | `beq` `bne` `blt` `bge` `bltu` `bgeu` |
| 跳转 | `jal` `jalr` `lui` `auipc` |
| 其他 | `fence`（空操作） |
| 环境 | `ebreak`（断点） `ecall`（系统调用） |
| 原创 | `slp`（等待：按周期数消耗时间，用于"要在 N 秒内完成"的关卡） |

伪指令（由汇编器展开）：`li` `la` `mv` `not` `neg` `nop` `j` `jr` `ret` `call`
`beqz` `bnez` `blez` `bgez` `bltz` `bgtz` `bgt` `ble` `bgtu` `bleu`
`seqz` `snez`。

### 3.2 寄存器

32 个 32 位通用寄存器 `x0`–`x31`，`x0` 恒为 0。汇编器/编译器同时接受标准名与 ABI 名，
编辑器里以标准名为主，剧情里用 ABI 名（`sp` `ra` `a0`）叙述。

调用约定（星咒的代码生成与手写汇编共用）：

| 寄存器 | 用途 |
|--------|------|
| `x0` | 恒 0 |
| `x1` ra | 返回地址 |
| `x2` sp | 栈指针（向下增长） |
| `x3` gp | **静态数据基址**（星咒编译器专用，指向数据段起点） |
| `x10`–`x17` a0–a7 | 函数参数 / 返回值（a0） |
| 其余 | 临时寄存器，自由使用 |

- 参数 i（0..7）放 `a{i}`；返回值放 `a0`。
- 被调函数需要保存 `ra` 时压栈；星咒编译器统一在函数序言里压 `ra`（简单、正确优先）。
- 数组作为参数传递时传地址。
- 内存布局（约定）：
  - `0x0000`–`0x00FF` 保留给运行时引导代码
  - `0x0100` 起为数据段（星咒编译产物）。汇编关卡可以在数据段里任意用 `0x1000` 起的位置
  - 栈：`0x0000F000` 向下增长（8 KiB 栈空间）
  - 上限：RAM 共 `0x00010000`（64 KiB）

### 3.3 内存映射

| 区间 | 用途 |
|------|------|
| `0x00000000`–`0x0000FFFF` | RAM（64 KiB，稀疏实现） |
| `0xF0000000` | **显示端口**（写 1 个字符，低 8 位有效；读恒 0） |
| `0xF0000004` | **输入端口**（读 1 个字符；队列空 → 读回 0 并在 `pause_on.mmio_read_empty` 时暂停） |
| `0xF0000008` | **魔力计**（只读，返回当前已消耗周期数；用于"功耗"类关卡） |
| 其他地址 | 段错误（运行错误） |

MMIO 模型与旧文档一致：每个输入地址一条 FIFO 队列，输出地址一份 append-only 记录；
`pause_on.mmio_write` 控制是否每次写都暂停（fail-fast vs 批量比对）。

### 3.4 系统调用（`ecall`，`a7` = 系统调用号）

| a7 | 名称 | 语义 |
|----|------|------|
| 0 | `SYS_EXIT` | 结束程序，退出码 = `a0` |
| 1 | `SYS_PUTC` | 输出字符 `a0` 到显示端口 |
| 2 | `SYS_PUTC_INT` | 以十进制输出整数 `a0` |
| 3 | `SYS_GETC` | 读一个字符到 `a0`（队列空 → 0） |
| 4 | `SYS_GETINT` | 读一个十进制整数到 `a0`（跳过空白，遇非数字停止） |
| 5 | `SYS_EXIT_CODE` | 同 0（保留，便于阅读） |
| 99 | `SYS_TIME` | 已消耗周期数 → `a0` |

`ecall` 是"程序结束"的唯一正常方式；星咒编译器在每个函数返回后由运行时库里调用它。
未使用的 `a7` 报运行错误。

### 3.5 暂停条件

`ecall`（默认开）、`ebreak`、`mmio_write`、`mmio_read_empty`、`error`、`limit`
—— 语义见 [`架构.md`](架构.md) §1.1（`PauseOn` 的 7 个开关与稳定的 `PauseReason::kind()` 字符串），
另有：命中 `slp` 时若 `pause_on.sleep` 为真则暂停（供"时间"类关卡观察，默认关）。

## 4. 星咒（C 子集）规格

星咒就是**一棵可教、可控的 C**，语法与 C 一致（这样玩家学到的知识直接可用），但只保证支持下列子集：

| 类别 | 支持 |
|------|------|
| 类型 | `int`（32 位）、`char`、`void`、`int*`、`char*`（一级指针）、`int[]`/`char[]`、`struct`（成员：整数/字符/指针/数组/嵌套结构体） |
| 声明 | 全局变量、全局数组、函数、局部变量、块作用域 |
| 运算符 | `+ - * / %` `== != < <= > >=` `&& \|\| !` `& \| ^ ~ << >>` `= += -= *= /= %= &= \|= ^= <<= >>=`、前置/后置 `++ --`、`?:`、`,`、`[]`、`&`取址、`*`解引用、`. ->`、强制转换 `(int)(char)(int*)` |
| 控制流 | `if/else`、`while`、`do-while`、`for`、`break`、`continue`、`return` |
| 函数 | 定义/调用/递归，最多 8 个整型参数 |
| 字面量 | 十进制、`0x` 十六进制、`'c'`、`'\n'` 等转义、字符串 `"..."` |
| 注释 | `//` `/* */` |
| 内建 | `putchar` `getchar` `print_int` `print_str` `exit`（由运行时库预置，玩家可直接调用） |

**不支持**（超集报错，错误信息给出人话提示）：浮点、`unsigned`/`long` 宽度差异（当作等价 32 位）、
多级指针、函数指针、`struct` 值传递与返回（按地址传参）、可变参数、预处理器（`#include` 等一律报错并提示
"遗迹里的星咒不需要它"）、`switch`（第四章不要求，若实现成本低可支持）。

**为什么是 C 子集而不是自创语言**：教学价值可迁移；且第四章的编译器关卡正好复刻玩家第二章写过的语言，
形成"我写过的语言 → 我写的编译器"的闭环。

## 5. 关卡格式（对旧 schema 的扩展）

关卡仍由两个文件组成：`compiler-content/src/cN_M.md`（叙事 + 编辑器配置 + 初始代码）
与 `compiler-content/src/tests/cN_M.json`（测例）。对旧 schema 的扩展：

### 5.0 内存与运行时约定（关卡设计必须遵守）

| 约定 | 值 | 说明 |
|------|-----|------|
| 代码段起点 | `0x00000000` | 汇编关卡的 `.text` 默认起点 |
| 数据段默认起点 | `0x1000` | 汇编关卡用 `.data` 时的默认地址 |
| 星咒编译产物 | 代码段从 0 开始，数据段从 `0x0100`，栈顶 `0x0000F000` 向下 | 由 starlang 决定，关卡作者不必关心 |
| MMIO 显示端口 | `0xF0000000` | 写入低 8 位即输出一个字符 |
| MMIO 输入端口 | `0xF0000004` | 读一个字符；队列空时读回 0（并把「空读」记下来） |
| MMIO 魔力计 | `0xF0000008` | 只读：已消耗周期数 |
| 输入结束 | 队列读空即视为输入结束 | 玩家程序读到 0 就结束（关卡设计保证输入里没有 `\0`） |

**汇编关卡可直接引用的运行时**：只有一个 `ecall` 系统调用，见 §3.4。
为了让汇编关卡不必手写字符串输出，汇编器提供 `.ascii` / `.asciz` 数据指示符，
玩家可以 `la x1, msg` + 循环 `lbu`/`sw` 输出。

### 5.1 编辑器配置新增字段

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `language` | `"asm"` \| `"c"` | `"asm"` | 决定编辑器用星之语还是星咒语法高亮、以及后端选择哪条编译路径 |
| `constraints.readonlyPrefix/Suffix` | number | 0 | 不变 |
| `constraints.lockedRegion` | `[start, end]` | — | 锁定任意行区间（1-based，含端点），比 prefix/suffix 灵活，用于"保护这段脚手架" |
| `constraints.highlight` | `number[]` | `[]` | 高亮提示行（不改只读性），用于引导阅读 |
| `constraints.suggested` | object | `{}` | 不变 |

### 5.2 测试配置新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `language` | `"asm"` \| `"c"` | 与编辑器配置一致 |
| `call` | object | **新增**：以"调用函数"方式运行（星咒关卡主力方式）<br>`{ "fn": "solve", "args": [3, 7] }`，返回值为 `a0` |
| `initial.memory.strings` | object | **新增**：`{ "0x1000": "hello" }` → 按 C 字符串（含结尾 `\0`）写入内存，便于给指针参数** |
| `expected.ret` | number | **新增**：期望的函数返回值（配合 `call`） |
| `expected.memory` | object | 不变，但支持 `"0x1000": { "string": "hello" }` 与 `"0x1000": [1,2,3]` 两种写法** |
| `goal.type = "scripted"` | — | `judge` 字段由项目内置的 Rust Judge 实现，按名字注册（不再有 EXE） |
| `goal.type = "output"` | — | **新增**：只比对输出流/终态的宽松判定（见下） |

**（**）** 编辑器/判定用的是"文本里的 JSON"，这些扩展由 `neomagic-core::config` 用 `serde_json::Value`
做宽容解析，不破坏旧的纯数字写法。

### 5.3 运行模式（`call` 有无）

| 模式 | 触发 | 语义 | 用在 |
|------|------|------|------|
| **函数模式** | 有 `call` | 运行时引导：设 `sp`、`gp`，把 `args` 放进 `a0..a7`，`jal` 到目标函数；函数 `ret` 后把 `a0` 当作返回值，与 `expected.ret` 比对 | 第二章、第三章前期 |
| **程序模式** | 无 `call` | 从入口（代码段第 0 条）开始执行，直到 `ecall` 结束；比对终态 + MMIO 输出 | 第一章、第三章后期、第四章 |

### 5.5 打字注意事项（关卡作者必读）

1. **`.md` 里的 `riscv` 块**：先 JSON 配置、单独一行 `---`、再初始代码。JSON 里**不能有注释**。
2. **测例 JSON**：`tests/cN_M.json`，字段名严格按 §5.2。`availableOps` 建议**只列本关要教的指令**。
3. 每条测例都要有可读的 `name`（提交失败时会给玩家看）。
4. 至少 3 条测例；覆盖典型值、边界值（0 / 1 / 负数 / 最大值）。
5. **不要**在 `expected.regs` 里检查与教学目标无关的寄存器 —— 那会误判合法解法。
6. 关卡作者必须同时给出**参考解**（写在 `compiler-content/solutions/cN_M.s` 或 `.c`），
   引擎的关卡自检会用它跑全部测例；跑不过说明测例或参考解有错。
7. `maxInstructions` 要给够但别太大（防止死循环卡住判定）。汇编关卡建议 2000–20000。

### 5.4 判定类型

| `goal.type` | 判定 | 说明 |
|-------------|------|------|
| `static` | 逐测例：比对 `expected.regs` / `expected.memory` / `expected.ret` / `output.mmio` | 主力 |
| `scripted` | 调用内置 Judge（Rust 函数），可随机化、可多轮交互 | 用于"排序校验""括号匹配校验"等 |
| `output` | 只比对 `expected.output`（MMIO 输出流 + 退出码），不比对寄存器 | 用于"编译结果必须一致"这类多解关卡 |

`output` 判定允许玩家用任意实现达成同一输出，避免"写死解法"误判。

## 6. 章节与关卡设计

### 6.1 第一章：魔法就是计算（星之语）

目标：让玩家在**没有任何编程经验**的前提下，用 15 个小关建立"寄存器 / 指令 / 内存 / 分支 / 循环 / 函数"
的完整心智模型，并在章末亲手完成一次"机关解锁"。节奏：概念 → 立即动手 → 反馈。

| 关卡 | 概念 | 任务 | 判定 |
|------|------|------|------|
| 1-1 | 寄存器与 `add` | 把 x1、x2 的和放进 x3 | 静态 |
| 1-2 | `addi` 立即数 | 把 x1+7 放进 x2 | 静态 |
| 1-3 | `sub` 与交换 | 计算 x1-x2 放进 x3，并把两数交换 | 静态 |
| 1-4 | `mul` / `div` / `rem` | 拆分一个数成商与余数 | 静态 |
| 1-5 | 内存与 `lw`/`sw` | 把 x1 的值搬到地址 0x1000，再搬回 x5 | 静态 |
| 1-6 | `li` 与数组写入 | 用 `sw` 把 1、2、3 写进连续地址 | 静态 |
| 1-7 | 分支 `beq`/`bne` | 两数相等放 1，否则放 0 | 静态（3 条测例） |
| 1-8 | 比较与分支 `blt`/`bge` | 求两数较大值 | 静态（含边界） |
| 1-9 | 标签与无条件跳转 `j` | 三条指令跳到远方标签，跳过"陷阱"指令 | 静态 |
| 1-10 | 循环雏形 | 求 1+2+…+n（n 在 x1），结果放 x10 | 静态（n=0,1,10,100） |
| 1-11 | 循环 + 内存 | 把数组前 n 个元素求和（数组在 0x1000） | 静态 |
| 1-12 | `ebreak` 与调试面板 | 故意放一个断点，观察第一次循环体时的寄存器 | 静态（只要 x10 最终正确） |
| 1-13 | 函数调用 `jal`/`jalr` | 写一个"平方"子程序并被调用 | 静态 |
| 1-14 | 栈与 `sp` | 用栈保存/恢复 `ra`，实现两层调用 | 静态 |

### 6.4 第四章：魔导符的编织（写编译器）

玩家写一个把**星咒子集**编译成**星之语文本**的程序。为了让"编译器输出"可判定，约定：
编译器读入星咒源码（字符流），输出目标星之语文本到显示端口；判定用 `output` 类型比对**规范化**

由我们的汇编器/模拟器执行 → 比对运行结果"的**端到端判定**（`judge: "compile_and_run"`），

| 4-6 | 语义检查 | 检测未声明变量与重复声明，输出错误码 |
| 4-7 | 代码生成：表达式 | 星咒表达式 → 星之语（寄存器栈式） |

| 4-12 | 终章：封印程序 | 用自己写的编译器编译封印程序，跑通并激活封印（剧情收束） |

## 7. Judge 注册表（替代 Special Judge EXE）

| 名字 | 参数 | 作用 |
|------|------|------|
| `sort_check` | `array_size`, `max_value`, `seed` | 随机生成数组 → 让玩家程序排序 → 校验结果有序且为原数组的重排 |
| `brackets_check` | `rounds`, `max_len` | 随机括号串 → 比对玩家输出 |
| `expr_check` | `rounds`, `max_operands`, `max_value` | 随机生成表达式 → 用 Rust 侧参考求值器算出答案 → 比对玩家输出 |
| `compile_and_run` | `program`, `fn`, `args`, `expected_ret` | 把玩家输出（星之语）交给汇编器 + 模拟器实际执行，比对运行结果 |

Judge 通过给模拟器预填 MMIO 输入、读取 MMIO 输出来工作，与静态判定共用同一套 Runner。

## 9. 为第五章预留

> ⚠ 这一节是**当时的设想**，其中一条与实现不符：`crates/starlang/src/ir.rs` **不存在**
> —— 星咒编译器现在是从 AST 直接生成星之语文本，中间没有独立 IR 层。
> 真正落地的情况见 [`架构.md`](架构.md) §1.3 与 §9 的差异清单。

- Simulator 已经支持完整 RV32IM，第五章的寄存器分配/指令选择可以直接复用。
- 星咒编译器原计划以 **线性 IR 指令列表**（`crates/starlang/src/ir.rs`）为中间层，
  第五章在 IR 上挂优化 Pass、不必改前端；**这一层要新增**（`parser.rs` → `codegen.rs` 目前是直连的）。
- 关卡判定已支持 `judge` 插件，优化类关卡（"周期数低于 N"）可通过新增
  Judge（读 `0xF0000008` 魔力计返回值）实现，无需改判定框架。
