# 目标与形态（`no_story` 分支总规划）

> 本文是 `no_story` 分支的**最高设计总纲**，回答三个核心问题：
> 1. 去掉剧情后，如何让零基础玩家看得懂、学得进、玩得爽，形成完整游戏闭环？
> 2. 放弃 `Tauri + mdBook` 转向网页版后，如何优雅承接后期的本地 C 语言工程开发？
> 3. 整个游戏按什么节奏分阶段落地，避免工程失控？
>
> 与旧文档冲突时，以本文与 [`架构.md`](架构.md) 为准。

---

## 一、产品定位与核心目标

### 1.1 我们要做一个什么样的游戏

**目标受众**：对汇编与编译原理完全零基础（甚至几乎没写过代码）但有好奇心的玩家，以及想通过动手项目彻底搞懂编译器的初学者。

**核心体验目标**：

- **看得懂**：不靠大段教科书文字，而是用**视觉隐喻 + 交互式动画**把抽象概念具象化。
- **走得顺**：难度曲线平滑爬升，每关只引入一个新概念，绝不出现“没教过就突然要求会”的断层。
- **有爽感**：高频、可见的正面反馈——从看到寄存器数据流动，到亲眼看着小机器人按自己翻译的指令行动，再到用自己写的编译器把 C 代码变成可运行的机器指令。
- **真本事**：学完不是“只会做选择题”，而是真正在本地拥有一个自己亲手写出来的 C 语言编译器项目。

### 1.2 为什么建立 `no_story` 分支

剧情创作（世界观推导、角色塑造、对话打磨）与核心玩法研发是两套完全不同的工作流。此前两者耦合导致关卡与架构反复被剧情牵制。
在 `no_story` 分支中：

- **暂时完全移除剧情与魔法名词**（不再使用星泠、岩舟、伊塔尔、星之语、星咒、记忆晶阵等包装）。
- **直接采用真实、准确的计算机术语**（CPU、寄存器、内存、栈、汇编、C 语言、Token、AST、编译器），配以直观的日常视觉隐喻（如寄存器 = CPU 桌面抽屉，内存 = 编号储物柜）。
- **保留未来叠加剧情的扩展口**：所有关卡数据与界面文案结构化分离，未来若恢复剧情，只需新增叙事层而不改核心玩法与判定逻辑。

## 二、零基础教学与游戏闭环设计

一个教学游戏能否“玩下去”，取决于**单关微观闭环**与**跨关宏观闭环**是否同时成立。

### 2.1 单关四步认知闭环（Micro Loop）

每一关都遵循统一的四步体验，杜绝一上来就扔给玩家一屏文字和空白编辑器：

| 步骤 | 玩家看到的 | 设计目的 |
|------|-----------|---------|
| **1. 一句话看懂目标（Before → After）** | 顶部固定任务卡：用可视化卡片展示「初始状态 / 输入」与「目标状态 / 期望输出」 | 5 秒内明白这关要解决什么问题，不需要从长文里找需求 |
| **2. 交互式微动画教学（Learn by Playing）** | 1~3 页可点击、可单步、可拖拽的交互演示（非静态长图或纯文字） | 让玩家先亲手“拨动”机制、看清数据怎么流，再引入对应语法/指令名 |
| **3. 脚手架动手实践（Guided Coding）** | 右侧独立 Playground：前期提供只读脚手架与填空引导，后期开放自由编写或本地 IDE 开发 | 降低“面对空白屏幕”的恐惧，把注意力集中在当前新概念上 |
| **4. 可视化运行与多维反馈（Feedback）** | 点击运行/提交后：看到动画回放、逐条测例点亮、失败时直观 Diff 与「一键调试该失败用例」 | 把报错从“挫败感”变成“线索”，让每次修改都能立刻看到进展 |

### 2.2 核心交互式动画组件体系（替代生硬文字）

转向现代 Web 应用的最大收益，就是能构建一套可复用的**教学可视化组件库**，贯穿全四章：

| 章节 | 核心可视化组件 | 玩家能看到 / 交互什么 |
|------|--------------|---------------------|
| **第一章（汇编）** | **CPU 数据流图 + 寄存器抽屉** | 点击或单步执行指令时，数值从源寄存器飞入 ALU 运算再落入目标寄存器；PC 指针沿代码高亮下移 |
| **第一章（汇编）** | **内存网格与栈帧动画** | 内存以地址格子阵列展示，写入时格块亮起；函数调用时直观看到栈帧像积木一样压入与弹出，`sp`/`ra` 箭头同步移动 |
| **第二章（C 语言）** | **C ↔ 汇编对照透视窗** | 鼠标悬停在任意一行 C 代码上，高亮它编译生成的 RISC-V 汇编块，帮玩家瞬间打通“高级语言和底层机器”的联系 |
| **第二章（C 语言）** | **指针与数据结构画布** | 指针显示为指向内存格子的真实箭头；数组、结构体、链表与树节点随执行动态渲染 |
| **第三章（迷你翻译器）** | **词法传送带 + 虚拟装置沙盘** | 左边看源码字符流过扫描头变成彩色 Token；右边看小机器人/机械臂在 2D 网格中按翻译出的指令逐步执行（移动、转向、抓取、放置） |
| **第四章（真编译器）** | **编译器流水线仪表盘 + AST 树视图** | 顶部展示 `源码 → Lexer → Parser → AST → Sema → Codegen → RISC-V 运行` 流水线进度条；点击任意阶段查看实时产物（Token 流 / 可折叠 AST 树 / 生成的汇编 / 模拟器执行结果） |

### 2.3 平滑难度增长曲线（锯齿形节奏）

为避免“前几关太简单、后面突然断崖式变难”，关卡编排采用**锯齿形递增曲线**：

```text
难度
 ▲                                              ★ 章末综合实战
 │                                        ╭────╯
 │                          ★ 阶段小综合   │ 概念C（微降）
 │                    ╭────╯              ╯
 │      ★ 阶段小综合   │ 概念B（微降）
 │ ╭───╯              ╯
 │ │ 概念A（脚手架填空）
 └──────────────────────────────────────────────▶ 关卡进度
```

- **单关单概念**：每关只引入 1 个新指令、新语法或新编译阶段。
- **脚手架逐步撤离**：同一章节内经历 `看动画填空（1~3 行） → 补全函数骨架 → 独立编写模块 → 本地工程集成`。
- **分级提示系统（3 级 Hint）**：玩家卡住时可按需逐级展开，而不是直接卡死：
  - Level 1（思路图解）：用示意图点破关键转折，不给代码；
  - Level 2（步骤拆解）：给出自然语言或伪代码步骤；
  - Level 3（关键片段）：给出核心几行写法或参考数据结构。
- **Wiki 概念图鉴**：系统性的指令表、C 语法速查、常见数据结构（动态数组、哈希表、AST 节点定义）全部收进可随时侧滑打开的 Wiki，关卡本身保持轻盈。

### 2.4 多维正面反馈与宏观闭环（Macro Loop）

1. **即时微反馈**：代码单步/倒退时寄存器与内存变更闪烁；测例逐条亮绿灯。
2. **失败零挫败**：测例失败时明确区分「编译错误 / 运行超时 / 输出不符 / 寄存器不符」，提供期望 vs 实际并排 Diff，并支持**一键把失败测例装入调试器单步回放**。
3. **通关结算卡片**：展示通过测例数、执行指令数与周期数（提供基准参考，但不强迫优化），以及「新解锁概念徽章」。
4. **可视化成长图谱**：
   - 关卡地图以**技能树/节点图**呈现，通关即点亮连线；
   - 第 3~4 章的本地工程每通过一关，编译器流水线仪表盘就永久点亮一个模块，形成强烈的“我在亲手造一个真实系统”的成就感。
5. **温和的进度引导**：主线默认按顺序通过解锁下一关（引导零基础玩家不跳级）；同时在设置中提供「开发者/自由探索开关」，允许有基础的玩家自由跳转或直接进入独立 Playground。

## 三、独立 Playground 与本地 C 项目联动设计

这是 `no_story` 分支在实现层面的核心创新：**让网页既能零门槛上手，又能无缝承接真实的本地 C 语言工程开发**。

### 3.1 独立 Playground 页面定位

Playground 不是藏在某几关里的小输入框，而是**全游戏共享的核心工作台**，有两种打开方式：

- **嵌入关卡视图（`/level/:id` 右侧）**：自动加载该关的初始代码/项目目标与专属测例集。
- **独立全屏页面（`/playground`）**：玩家随时可以切进来自由写汇编/C 做实验，或者挂载任意已解锁关卡的测例集进行专项调试。

### 3.2 两种无缝切换的工作模式

| 维度 | 模式 A：在线编辑模式（WASM） | 模式 B：本地项目模式（`nmc-bridge`） |
|------|----------------------------|----------------------------------|
| **适用阶段** | 第 1 章、第 2 章、日常小实验 | 第 3 章、第 4 章（也兼容第 1~2 章进阶玩家） |
| **环境要求** | **零安装**，打开浏览器即玩 | 启动本地轻量工具 `nmc-bridge` + 本机 `gcc`/`clang` |
| **写代码位置** | 网页内置代码编辑器（支持高亮、行号、只读脚手架） | **玩家自己的本地 IDE**（VS Code / CLion / Vim 等） |
| **构建与测试** | 浏览器内 WASM 引擎毫秒级执行 | 网页端识别本地项目，一键触发本地编译、运行、模拟器判定 |
| **调试与可视化** | 完整支持单步、倒退、CPU/内存/栈动画 | 同样完整支持！玩家编译器产出的汇编会送回网页端做可视化回放与单步调试 |

### 3.3 本地项目联动的完整玩家闭环

为了不让零基础玩家被“配置本地环境”劝退，第 3 章第 1 关专门设计为**环境连通引导关**：

1. **一键获取项目脚手架**：网页端提供「下载第 3 章 C 项目模板（ZIP）」或命令行 `nmc-bridge init`，内含干净的 `src/`、`Makefile` 和项目识别文件 `nmc.project.json`。
2. **启动本地桥接**：玩家在项目目录运行 `nmc-bridge`（未来可提供双击托盘版）。
3. **网页端自动识别**：Playground 顶部状态栏自动从灰色变为绿色，显示「已连接本地项目：`my-mini-translator`｜工具链：`gcc` 就绪」。
4. **日常开发循环（极低摩擦）**：
   - 玩家在本地 IDE 修改 C 代码并保存；
   - 网页 Playground 可开启 **Auto-Watch（保存即自动构建并跑当前关测例）**，或手动点击「构建 & 测试」；
   - 网页端实时展示：① C 编译日志（报错可直接看文件与行号）；② 玩家程序的输出产物（Token / 装置指令 / RISC-V 汇编）；③ 模拟器运行结果与动画回放；④ 逐条测例判定与 Diff。

## 四、四章内容与能力衔接总览

详细关卡表与规格见 [`总设计.md`](总设计.md)，此处明确各章的**教学定位与衔接逻辑**：

| 章 | 定位 | 玩家工具 | 与下一章的衔接 |
|----|------|---------|---------------|
| **第一章：RISC-V 汇编入门** | 拆掉计算机黑盒 | 在线 Playground（WASM） | 理解寄存器、内存、栈帧、函数调用约定后，看懂“高级语言编译出来到底是什么” |
| **第二章：C 语言与编译前置基础** | 掌握写编译器的武器 | 在线 Playground（WASM）+ C↔汇编对照视图 | 不教无关的竞赛偏题，重点打通指针、字符串扫描、结构体、递归、动态数组/树/符号表 |
| **第三章：迷你翻译器** | 第一次造翻译系统 | **本地 C 项目 + 网页 Playground** | 把简单的“机器人脚本”翻译成 6~8 条指令的虚拟装置码并在网页跑动画；熟悉本地开发闭环与词法/语法/生成三段论 |
| **第四章：真正的编译器** | 完整工程实战 | **本地 C 项目 + 网页 Playground** | 复用第 3 章建立的工程习惯，把目标从“虚拟装置”升级为真实的 **RV32IM 汇编**，源语言升级为第 2 章学过的 **C 子集**，形成完美首尾闭环 |

> **第五章（预留扩展）**：多级 IR、寄存器分配、常量折叠/死代码消除等优化 Pass，以及带流水线/分支预测模型的周期评分榜。当前仅在架构与判定接口上预留，不投入开发。

## 五、分阶段实施路线图

为保证项目随时处于“可运行、可试玩”的健康状态，按四个阶段推进：

| 阶段 | 核心交付 | 验收标准（闭环检查） |
|------|---------|-------------------|
| **Phase 1：Web 壳与 WASM 闭环** | 搭建 `web/` 前端框架与 `crates/nmc-wasm`；实现独立 Playground（在线模式）、关卡地图与第 1 章前 5 关的交互动画重构 | 零安装打开浏览器，能通过动画学懂并玩通第 1 章前 5 关，支持单步/倒退与存档 |
| **Phase 2：前两章可视化重构** | 补全第 1~2 章全部核心交互可视化组件（CPU/内存/栈/C↔汇编对照/指针画布），迁移并优化前两章 29 关内容，上线侧滑 Wiki 图鉴 | 零基础玩家可纯网页流畅通关第 1~2 章，所有关卡通过引擎自检 |
| **Phase 3：本地桥接与第 3 章闭环** | 开发 `crates/nmc-bridge`（项目识别、监听、gcc 构建、运行与超时保护）；实现 Playground「本地项目模式」与第 3 章虚拟装置动画沙盘 + 8~10 关 | 玩家在本地 VS Code 改 C 代码，网页端自动构建、跑通小机器人动画并通关第 3 章 |
| **Phase 4：第 4 章真编译器工程** | 设计并实现第 4 章 12~14 关（持续演进的本地 C 编译器项目）、流水线仪表盘、AST 可视化与端到端 `compile_and_run` 判定 + 参考编译器自检 | 玩家用本地 C 项目逐关构建完整编译器，最终编译真实 C 程序并在网页 RISC-V 模拟器中跑通 |

## 六、待细化事项（进入对应阶段前确认）

1. **Web 前端框架选型**：推荐 `Vite + TypeScript + React + Tailwind CSS`（生态最适合做 SVG/Canvas 交互动画与代码编辑器集成如 CodeMirror 6 / Monaco），在 Phase 1 动工前最终拍板。
2. **第 4 章输出形态**：默认采用**单文件汇编输出**（玩家编译器直接吐出完整 RISC-V 汇编文本，交由 `riscv-assembler` 一次汇编，无需复杂链接器）；是否在第 4 章末尾或第 5 章引入多文件链接，留待 Phase 4 评估。
3. **第 3 章虚拟装置细节**：具体网格主题（如仓储机械臂 / 矿车轨道 / 逻辑电路节点）在 Phase 3 开工前敲定，指令集核心结构已在 [`总设计.md`](总设计.md) 定义。
