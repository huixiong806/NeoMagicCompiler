# 存档与草稿格式

> 本文描述**当前实现**的两个持久化位置，代码依据：
> `crates/neomagic-core/src/progress.rs`（全局存档）与
> `compiler-content/frontend/src/core/storage.ts`（编辑器草稿）。
> 两者职责不同，**不要合并**：存档是"通关记录"（后端写、跨关卡），
> 草稿是"还没提交的代码"（前端写、按关卡隔离、只在本机 WebView 里）。

---

## 1. 全局存档 `user_progress.json`

### 1.1 位置

| 场景 | 路径 |
|------|------|
| 桌面版（正常运行） | Tauri 的**应用数据目录**下，Windows 上约为 `%APPDATA%\com.neomagiccompiler.app\user_progress.json`（目录名由 `app/src-tauri/tauri.conf.json` 的 `identifier` 决定） |
| 拿不到应用数据目录时的兜底 | 当前工作目录下的 `user_progress.json`（`default_progress_path(None)`） |

启动时会往 stderr 打一行 `[存档] <路径>`（`app/src-tauri/src/lib.rs` 的 `setup`），
排查"进度没记住"时先看这一行。

写入是**整文件覆盖**：`UserProgress::save()` 先刷新 `lastModified`，再 `create_dir_all` 父目录，
然后 `serde_json::to_string_pretty` 写回。没有增量写入，也没有加锁文件。

### 1.2 格式（`version = 1`）

```json
{
  "version": 1,
  "lastModified": "2026-02-01T00:00:00Z",
  "levels": {
    "1-1": {
      "levelId": "1-1",
      "passed": true,
      "completedAt": "2026-02-01T00:00:00Z",
      "attempts": 3,
      "bestScore": 100
    }
  },
  "settings": { "showHints": true }
}
```

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `version` | number | `1`（常量 `PROGRESS_VERSION`） | 格式版本。**破坏性变更必须 +1**，并在 `migrate()` 里处理旧版本 |
| `lastModified` | string | 当前时间的 ISO 8601 | 每次 `save()` 刷新 |
| `levels` | object | `{}` | 关卡 ID（`"1-1"`）→ 通关记录 |
| `levels.<id>.levelId` | string | `""` | 与键重复存一份 |
| `levels.<id>.passed` | bool | `false` | **一旦为真就不再变假**（之后再失败也只加尝试次数） |
| `levels.<id>.completedAt` | string? | 省略 | 首次通过的时间（ISO 8601）。为 `None` 时整个键不出现 |
| `levels.<id>.attempts` | number | `0` | 累计提交次数（每次提交都 +1，无论成败） |
| `levels.<id>.bestScore` | number? | 省略 | 历史最高分（取 `max`） |
| `settings.showHints` | bool | `true` | 是否显示行内提示（前端读，后端只负责存） |

时间戳由 `now_iso()` 生成，格式固定为 `YYYY-MM-DDTHH:MM:SSZ`（UTC，无毫秒、无时区偏移）。
实现里没有引入时间库，用 Unix 秒 + Howard Hinnant 的 `civil_from_days` 换算。

### 1.3 版本与迁移

- 读文件时走 `migrate()`：
  - `version < 1` → 直接把版本号改成 1（目前没有真正的旧格式，这一步是给将来留位的占位实现）；
  - `version > 1` → **原样返回，不覆盖 `version`**。也就是"新版存档被旧版游戏打开"时，
    旧版会尽量读、并把未知的未来字段一起写回去，而不是把版本号倒退。
- 写文件时永远写 `PROGRESS_VERSION`（当前 1）。
- **加字段的规矩**：一律给 `#[serde(default)]`，这样缺字段的旧存档能直接读；
  只有"语义变了、旧值会被读错"时才升 `version` 并写迁移分支。

### 1.4 损坏处理

`UserProgress::load()` 遇到 JSON 解析失败（文件被截断、被人手改坏）：

1. 把坏文件**重命名**为 `user_progress.json.bak`（同目录；覆盖已有的 `.bak`；重命名失败也不报错）；
2. 返回一份**全新空存档**（`Default`）。

所以进度不会因为一次解析失败就消失，但也不会自动从 `.bak` 恢复 —— 要救回进度，
需要手工把 `.bak` 改回 `user_progress.json`，并确保内容是合法 JSON。

文件**不存在**是正常情况（首次启动）：直接返回空存档，不创建文件、不报警。

### 1.5 谁在写它

| 动作 | 效果 |
|------|------|
| `submit_code`（`AppState::submit`） | `progress.record(level, passed, score)`：`attempts += 1`、刷新 `bestScore`、首次通过时记 `completedAt` 并置 `passed`；随后立刻 `save()` |
| `save_progress`（`AppState::save_progress`） | 应用 `showHints`；`lastLevel` 只打日志、**不落盘**（关卡顺序由 mdBook 目录决定）；然后 `save()` |
| `load_progress` | 返回内存里的整份存档（启动时读过一次） |

**存档写失败不会吞掉判定结果**：`submit` 里写盘失败只 `eprintln!` 一行日志，判定结果照常返回给前端
（判定的价值高于记录）。测试用"进程 id + 线程 id"拼出临时目录，不污染真存档。

## 2. 编辑器草稿（localStorage）

| 项 | 值 |
|----|----|
| key | `level-{关卡ID}-draft`，例如 `level-1-1-draft`（`storageKey()` 生成） |
| 结构 | `{ "code": "...", "savedAt": "<ISO 8601>", "level": "1-1" }` |
| 保存时机 | 编辑停止 **500 ms** 后（`AUTO_SAVE_DEBOUNCE_MS` 防抖） |
| 恢复时机 | 打开关卡时 `restoreDraft(levelId)`；解析失败或结构不对就删掉这个 key 并返回 `null` |
| 作用域 | 浏览器 `localStorage`，按站点/WebView 隔离。换机器、清缓存、改 Tauri 的 `identifier` 都会丢 |

注意：工具栏的「保存文件」是**把代码下载成本地文件**，与草稿无关；
「加载文件」同样只影响编辑器内容，不写草稿。

**为什么草稿不放进 `user_progress.json`**：草稿的写入频率是"每次打字"，
存档的写入频率是"每次提交"。混在一起会让存档文件变成高频写盘对象，
也让前端必须为"保存草稿"跑一次 IPC。

两者之间**唯一的联系是关卡 ID**：存档回答"这关我过了没有"，草稿回答"我上次写的代码是什么"。
只清草稿不影响通关记录；只清存档也不影响手里正在写的代码。
