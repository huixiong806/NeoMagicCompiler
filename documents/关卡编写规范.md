# 关卡编写规范（`no_story` 强游戏化网页版）

> 本文面向**编写或重构关卡的作者（或 AI）**。
> `no_story` 分支已取消剧情与魔法名词，全面转向**「先手玩沙盘，再写代码」强游戏化教学 + 独立 Playground（在线编辑 / 本地单文件 / 本地 C 工程）**。
> 核心规格见 [`总设计.md`](总设计.md)，技术架构见 [`架构.md`](架构.md)。

---

## 1. 单关目录结构（`content/levels/cN_M/`）

| 文件 | 必需 | 作用 |
|------|:---:|------|
| `meta.json` | ✅ | 元信息、工作模式、前置依赖、知识点、**强交互沙盘配置（`sandbox`）**、3 级提示 |
| `lesson.md` | ✅ | 精简任务说明（≤300 字，只写目标与关键规则；系统性原理进 `content/wiki/`） |
| `starter.s` 或 `starter.c` | 第 1~2 章 | 在线与本地单文件模式的初始代码和脚手架 |
| `tests.json` | ✅ | 测例、白名单、判定类型（`static` / `output` / `draw_sim` / `compile_and_run` / `scripted`） |
| `solution.s` / `solution.c` / 参考阶段 | ✅ | **参考解**（引擎自检用它验证关卡可解） |

命名约定：`N` 为章号，`M` 为关号，**不补零**（如 `c1_5`，关卡 ID 为 `"1-5"`）。

## 2. `meta.json` 规范（含强交互沙盘声明）

```json
{
  "id": "1-4S",
  "chapter": 1,
  "order": 4.5,
  "kind": "challenge",
  "title": "支线挑战：零空间原地交换",
  "mode": "online",
  "allowLocalFile": true,
  "language": "asm",
  "prerequisites": ["1-4"],
  "parInstructions": 4,
  "concepts": ["in-place-swap", "modular-arithmetic"],
  "goalSummary": {
    "before": "t0 = a，t1 = b；其他通用寄存器禁用",
    "after": "仅用 add 与 sub 就地交换 t0 与 t1"
  },
  "sandbox": {
    "type": "manual-cpu",
    "modules": ["regs", "alu"],
    "recordToAsm": true,
    "focusRegs": ["t0", "t1"],
    "aluOps": ["+", "-"],
    "warmupPuzzle": {
      "prompt": "没有暂存槽 t3 了！先合并出两数之和，再反推原值完成互换。",
      "initial": { "regs": { "t0": 10, "t1": 3 } },
      "goal": { "regs": { "t0": 3, "t1": 10 } }
    }
  },
  "editor": {
    "readonlyPrefix": 1,
    "readonlySuffix": 1
  },
  "hints": [
    { "level": 1, "type": "diagram", "content": "先让 t0 保存两数之和 a + b。" },
    { "level": 2, "type": "steps", "content": "1. t0 = t0 + t1；2. t1 = t0 - t1；3. t0 = t0 - t1。" },
    { "level": 3, "type": "snippet", "content": "add t0, t0, t1\nsub t1, t0, t1\nsub t0, t0, t1" }
  ],
  "wikiRefs": ["rv32-arithmetic"]
}
```

> **节点类型（`kind`）与 DAG 解锁**：
> - `lesson`（概念关）：单关只引入 1 个新概念；
> - `practice`（巩固关）：零新指令/零新语法，每 2~3 个概念关后必插 1 关用于消化组合；
> - `challenge`（支线挑战）：挂接在巩固关旁（`order` 可用小数如 `4.5`，目录名 `c1_4s`），**不阻塞下一主线关解锁**，可选填写 `parInstructions`（静态机器码总条数目标，参考解必须满足 `<= parInstructions`）。

### 2.1 四套强交互沙盘类型（`sandbox.type`）

| `sandbox.type` | 适用章节 | 必备配置项 |
|---------------|---------|----------|
| `manual-cpu` | 第 1 章 | `warmupPuzzle`（手玩热身谜题）+ `recordToAsm: true`（将手工操作自动录制成汇编对照） |
| `memory-canvas` | 第 2 章 | `focusVars` / `showAsmDiff: true` / `predictQuestions`（执行前点击预测哪格会变） |
| `lexer-ast-lab` | 第 3~4 章前端 | `interactiveMode: "lexer" \| "ast"` + `sampleInput`（供玩家手切 Token 或手拼语法树） |
| `pipeline-stage` | 第 3~6 章后端 | `activeStages`（如 `["lex", "parse", "codegen", "run"]`）+ `outputView: "draw-canvas" \| "riscv-monitor"` |

### 2.2 工作模式字段

- `mode`: `"online"`（第 1~2 章默认）或 `"local-project"`（第 3~6 章默认）。
- `allowLocalFile`: 第 1~2 章设为 `true`，允许玩家在 Playground 中切换为本地单文件监听模式（用 VS Code 写 `.s`/`.c`）。
- `projectSpec`: 仅 `local-project` 关填写，指定调用本地玩家可执行文件的阶段与模板，例如 `{ "stage": "codegen", "template": "chapter4-starter" }`。

## 3. 零基础强游戏化写作准则

1. **先手玩，再编码**：凡引入全新概念的关卡，必须在 `sandbox` 中配置一个 30~60 秒就能玩通的**热身手玩谜题**（拖数字、连指针、切 Token、拼 AST），禁止直接甩一屏纯文字定义。
2. **精简正文**：`lesson.md` 控制在 150~300 字以内，只写“本关要实现什么”与“关键约束”；完整语法表与数据结构参考放 `content/wiki/` 并通过 `wikiRefs` 关联。
3. **单关单概念，零跳跃**：严禁出现前面尚未教过的指令、C 语法或数据结构；第 4 章核心关严禁出现数组/指针/`struct`（这些留到第 5 章）。
4. **直白真实术语**：不写剧情对话、不使用魔法包装词。
5. **3 级提示必须可操作**：Level 1 给思路方向，Level 2 给步骤拆解，Level 3 给关键代码片段，禁止写“再想想”。

## 4. `tests.json` 测试配置规范

### 4.1 第 1~2 章（`static` / `output`）

```json
{
  "level": "1-5",
  "language": "asm",
  "availableOps": ["li", "lw", "sw", "ecall"],
  "forbiddenRegs": [],
  "maxInstructions": 5000,
  "goal": {
    "type": "static",
    "tests": [
      {
        "name": "写入并读回 42",
        "initial": { "regs": { "x1": 42, "x2": 4096 }, "memory": {} },
        "expected": { "regs": { "x5": 42 }, "memory": { "0x1000": 42 } }
      }
    ]
  }
}
```

- 函数模式写 `"call": { "fn": "solve", "args": [3, 7] }` + `"expected": { "ret": 10 }`（第 2 章主力，引导桩固定在 `0x0800`）。
- 字符串内存写作 `{"string": "abc"}`；输出文本比对按行规范化（去首尾空白与空行）。
- `expected` **只比对与教学目标相关的字段**，避免误杀合法写法。

### 4.2 第 3 章绘图关（`draw_sim`）

```json
{
  "level": "3-7",
  "language": "draw-script",
  "maxInstructions": 20000,
  "goal": {
    "type": "draw_sim",
    "tests": [
      {
        "name": "绘制四段递增螺旋线",
        "input": { "text": "let i = 0; pen(1); while (i < 4) { move(20 + i * 10); turn(90); i = i + 1; }" },
        "expectedSegments": [
          [0, 0, 20, 0],
          [20, 0, 20, 30],
          [20, 30, -20, 30],
          [-20, 30, -20, -20]
        ]
      }
    ]
  }
}
```

### 4.3 第 4~5 章代码生成关（`compile_and_run`）

```json
{
  "level": "4-9",
  "language": "c",
  "maxInstructions": 50000,
  "goal": {
    "type": "compile_and_run",
    "tests": [
      {
        "name": "递归计算 5 的阶乘",
        "program": "int fact(int n) { if (n <= 1) return 1; return n * fact(n - 1); } int main() { return fact(5); }",
        "expected": { "exitCode": 120 }
      }
    ]
  }
}
```

## 5. RISC-V 引擎避坑清单（写汇编关卡与参考解必读）

1. **`a7` 是 `x17`，不是 `x11`**：系统调用号写错到 `x11` 会导致 `a7 == 0`，每次 `ecall` 直接退出程序。
2. **不要把 `x1` 当临时寄存器**：`x1` 是 `ra`，`jal`/`call` 会覆盖它；临时值用 `t0`–`t6`。
3. **跨 `jal` 保存的值放 `s0`–`s11` 或压栈**：`t0`–`t6`、`a0`–`a7` 随时可能被子函数改写；`ecall` 本身只写 `a0`。
4. **MMIO 输入端口读宽度**：`0xF0000004` 上无论用 `lw`/`lh`/`lbu`/`lb`，都只消费 1 个字符（空返回 0）。
5. **`.word` 不自动对齐**：`.asciz`/`.byte` 后接 `.word` 必须显式写 `.align 4`，否则触发未对齐访存错误。
6. **“空输出”测例必须加 `expected.memory`**：输出规范化会丢空行，单靠 `output.text: ""` 会放过空骨架。
7. **编辑器约束行号范围**：`readonlyPrefix + readonlySuffix` 必须严格小于初始代码总行数；`suggested`/`highlight`/`hidden` 行号不得越界。

## 6. 关卡交付自检清单

- [ ] 单关目录齐全：`meta.json`、`lesson.md`、`tests.json`、参考解，关卡 ID 三处一致
- [ ] `goalSummary`、`sandbox` 强交互配置、3 级 `hints` 全部填写完整
- [ ] 无剧情/魔法残留词汇，未超前引入未教概念
- [ ] 测例 ≥ 3 条，含典型值与边界值，`name` 通俗易懂
- [ ] `cargo test -p neomagic-core selfcheck -- --nocapture` 全绿
- [ ] `cargo test -p neomagic-core every_level_page_and_test_config_are_consistent` 全绿
