# 关卡编写规范（`no_story` 可视化网页版）

> 本文面向**编写或重构关卡的作者（或 AI）**。
> `no_story` 分支已取消剧情与魔法名词，全面转向**零基础可视化教学 + 独立 Playground（支持在线编辑与本地 C 项目双模式）**。
> 核心规格见 [`总设计.md`](总设计.md)，技术架构见 [`架构.md`](架构.md)。

---

## 1. 一个关卡的目录结构

不再把所有内容塞进 mdBook 的单文件 `riscv` 代码块中，而是改为结构清晰的**单关目录**（`content/levels/cN_M/`）：

| 文件 | 必需 | 作用 |
|------|:---:|------|
| `meta.json` | ✅ | 关卡元信息、工作模式（在线 / 本地项目）、前置依赖、知识点标签、交互动画声明、3 级提示 |
| `lesson.md` | ✅ | 简短精炼的任务说明（任务目标、Before/After 示意、按需穿插交互动画槽位） |
| `starter.s` 或 `starter.c` | 在线关 | 在线模式初始代码与只读脚手架（本地项目关可省略，改由 `templates/` 提供工程脚手架） |
| `tests.json` | ✅ | 测例、白名单、判定方式（`static` / `output` / `bot_sim` / `compile_and_run` / `scripted`） |
| `solution.s` / `solution.c` / 参考阶段 | ✅ | **参考解**（自检守门人用它验证关卡确定可解） |

命名约定：`N` 是章号，`M` 是关号，**不补零**（如 `c1_5`，关卡 ID 为 `"1-5"`）。

## 2. `meta.json` 规范

```json
{
  "id": "1-5",
  "chapter": 1,
  "number": 5,
  "title": "内存读写：lw 与 sw",
  "mode": "online",
  "language": "asm",
  "prerequisites": ["1-4"],
  "concepts": ["memory", "lw", "sw", "address"],
  "goalSummary": {
    "before": "x1 = 42，内存 0x1000 处为空",
    "after": "将 x1 写入 0x1000，再从 0x1000 读回 x5"
  },
  "visualizer": {
    "type": "cpu-memory",
    "focusRegs": ["x1", "x5"],
    "watchMemory": ["0x1000", "0x1004"],
    "walkthrough": [
      {
        "title": "第一步：把值存进内存格子",
        "highlightCode": "sw x1, 0(x2)",
        "animation": { "from": "reg:x1", "to": "mem:0x1000", "label": "写入 4 字节" },
        "caption": "sw 把寄存器里的数字放进指定地址的储物柜。"
      }
    ]
  },
  "editor": {
    "readonlyPrefix": 2,
    "readonlySuffix": 1,
    "suggested": { "3": "lw x5, 0(x2)" }
  },
  "hints": [
    { "level": 1, "type": "diagram", "content": "先确认基址寄存器里存的是 0x1000，再做偏移为 0 的读取。" },
    { "level": 2, "type": "steps", "content": "1. 使用 sw 写入；2. 使用 lw 读入 x5。" },
    { "level": 3, "type": "snippet", "content": "lw x5, 0(x2)" }
  ],
  "wikiRefs": ["rv32-memory", "endianness"]
}
```

### 2.1 在线模式 vs 本地项目模式字段

| 字段 | 值 | 说明 |
|------|-----|------|
| `mode` | `"online"` \| `"local-project"` | 第 1~2 章默认 `"online"`；第 3~4 章默认 `"local-project"` |
| `language` | `"asm"` \| `"c"` \| `"bot-script"` | 决定语法高亮与执行管线 |
| `projectSpec` | 对象（仅 `local-project` 关） | 指定调用本地玩家可执行文件时的参数，例如 `{ "stage": "lex", "template": "chapter4-starter" }` |
| `visualizer.type` | 枚举 | 可选：`cpu-alu` / `cpu-memory` / `cpu-stack` / `c-asm-diff` / `pointer-canvas` / `lexer-belt` / `bot-grid` / `compiler-pipeline` |

## 3. 零基础视觉化写作规范（核心要求）

写 `lesson.md` 与 `meta.json` 时，必须严格遵守以下教学原则：

1. **禁止大段枯燥文本**：`lesson.md` 正文控制在 **150~300 字**以内，只写“这一关要解决什么问题”与“关键约束”；系统性原理与长篇参考放到 `content/wiki/`，通过 `wikiRefs` 挂接。
2. **先看图/动画，再出术语**：每个新概念必须先在 `visualizer.walkthrough` 中用 1~3 步交互演示把“数据怎么动”演出来，再用一句话给它起正式名字（如 `lw`、栈帧、Token）。
3. **单关单概念，零跳跃**：正文、初始代码与测例中，**绝对不能出现前面关卡没教过的指令、语法或数据结构**。
4. **直白、真实的计算机术语**：不要使用魔法/剧情词汇；使用真实术语 + 日常比喻（例如“寄存器 = CPU 桌面上的 32 个数字槽”、“内存 = 按编号排列的储物柜”）。
5. **3 级提示必须写实**：禁止写“再仔细想想”“观察一下规律”这类无效提示。Level 1 点出思路方向，Level 2 给出步骤，Level 3 给出关键代码片段。

## 4. `tests.json` 测试配置规范

### 4.1 顶层字段

```json
{
  "level": "1-5",
  "language": "asm",
  "availableOps": ["li", "lw", "sw", "ecall"],
  "forbiddenRegs": [],
  "maxInstructions": 5000,
  "goal": {
    "type": "static",
    "tests": [
      {
        "name": "读取 42",
        "initial": { "regs": { "x1": 42 }, "memory": {} },
        "expected": { "regs": { "x5": 42 }, "memory": { "0x1000": 42 } }
      }
    ]
  }
}
```

| 字段 | 必需 | 说明 |
|------|:---:|------|
| `level` | ✅ | 与目录名一致，如 `"1-5"` |
| `language` | ✅ | `"asm"` / `"c"` / `"bot-script"` |
| `availableOps` | 在线汇编关 | 允许的助记符白名单；`[]` 表示全部允许 |
| `forbiddenRegs` | 可选 | 禁止使用的寄存器列表（`x9` 或 `s1`）；`[]` 为不限制 |
| `maxInstructions` | ✅ | 单测例最大指令数，防死循环 |
| `goal` | ✅ | 判定类型：`static` / `output` / `bot_sim` / `compile_and_run` / `scripted` |

### 4.2 第 3~4 章本地项目关卡测例示例

**第 3 章（`bot_sim` 判定）**：

```json
{
  "level": "3-6",
  "language": "bot-script",
  "maxInstructions": 10000,
  "goal": {
    "type": "bot_sim",
    "tests": [
      {
        "name": "重复搬运 3 个箱子",
        "input": { "text": "repeat 3 { move; pick; }\nright;\nmove;\ndrop;\n" },
        "map": { "width": 5, "height": 3, "start": [0, 0, "E"], "items": [[1,0], [2,0], [3,0]], "target": [[3,1]] }
      }
    ]
  }
}
```

**第 4 章（`compile_and_run` 端到端判定）**：

```json
{
  "level": "4-10",
  "language": "c",
  "maxInstructions": 50000,
  "goal": {
    "type": "compile_and_run",
    "tests": [
      {
        "name": "递归计算 5 的阶乘",
        "program": "int fact(int n) { if (n <= 1) return 1; return n * fact(n - 1); } int main() { return fact(5); }",
        "expected": { "exitCode": 120 }
      }
    ]
  }
}
```

### 4.3 测例通用字段速查（`static` / `output`）

- `call`：`{ "fn": "solve", "args": [3, 7] }` → 函数模式（第 2 章主力，引导桩在 `0x0800`，返回值取 `a0`）。
- `initial.regs` / `initial.memory` / `initial.sp`：初始状态；字符串内存写作 `{"string": "abc"}`。
- `input.text` / `output.text`：MMIO 输入输出字符流（`0xF0000004` / `0xF0000000`）。输出比对按行规范化（去首尾空白与空行）。
- `expected.ret` / `expected.regs` / `expected.memory` / `expected.exitCode`：**只比对列出的项**，不要检查与教学目标无关的寄存器。

## 5. RISC-V 引擎避坑清单（写汇编关卡与参考解必读）

以下均为真实踩过的坑，已通过引擎单元测试固化，写关时务必遵守：

1. **`a7` 是 `x17`，不是 `x11`**：`x11` 是 `a1`。若把系统调用号错写进 `x11`，`a7` 恒为 0，每次 `ecall` 都会被当作退出程序，表现为“程序瞬间结束、输出全空”。
2. **不要把 `x1` 当普通临时寄存器**：`x1` 即 `ra`，`jal`/`call` 会覆盖它。临时值请用 `t0`–`t6`。
3. **跨 `jal` 保存的值必须放 `s0`–`s11` 或压栈**：`t0`–`t6` 与 `a0`–`a7` 随时会被辅助函数覆盖；`ecall` 系统调用本身**只写 `a0`**，不破坏 `t` 寄存器。
4. **MMIO 输入端口读取宽度语义**：从 `0xF0000004` 读取时，`lw`/`lh`/`lbu`/`lb` **都只消费 1 个字符**（队列空返回 0）。
5. **`.word` 不会自动对齐**：在 `.asciz` / `.byte` 后紧接 `.word` 时，必须显式写 `.align 4`，否则模拟器会报未对齐访问错误。
6. **“空输出”测例必须加额外内存校验**：由于输出文本比对会忽略空行，仅靠 `output.text: ""` 会让什么都没做的空骨架误通过；务必配合 `expected.memory` 验证逻辑确实执行过。
7. **编辑器约束行号范围**：`readonlyPrefix + readonlySuffix` 必须严格小于初始代码总行数；`suggested`/`highlight`/`hidden` 的行号必须是 1-based 代码行号，不能越界。

## 6. 关卡交付自检清单

- [ ] 目录结构完整：`meta.json`、`lesson.md`、`tests.json`、参考解齐全且 ID 一致
- [ ] `goalSummary` 清晰写出 Before/After；`visualizer.walkthrough` 至少包含 1 个交互步骤
- [ ] 无剧情/魔法残留词汇，未引入尚未教学的前置概念
- [ ] 提供完整的 3 级 `hints`，且每级提示具体可操作
- [ ] 测例 ≥ 3 条，覆盖常规值与边界值（0 / 1 / 负数 / 空输入），`name` 易读
- [ ] `cargo test -p neomagic-core selfcheck -- --nocapture` 通过
- [ ] `cargo test -p neomagic-core every_level_page_and_test_config_are_consistent` 通过
