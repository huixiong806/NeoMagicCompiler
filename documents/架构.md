# 架构设计（网页化 + 强交互沙盘 + 本地项目桥接）

> 本文定义 `no_story` 分支的**已拍板系统架构**，明确前端技术栈、双部署形态、4 套强游戏化沙盘的数据驱动架构、现有 Rust 核心复用清单，以及 `nmc-wasm` / `nmc-bridge` 协议。
> 原 `Tauri 2 + mdBook` 方案已废弃，迁移路径见 §7。

---

## 1. 总体架构：Web SPA + 双执行后端 + 双部署形态

```text

│  表示层  web/  (Vite + TypeScript + React + Tailwind CSS + CodeMirror 6)      │
│   ├─ 关卡地图 (Skill Tree)                                                    │
│   ├─ 4 套强游戏化可玩沙盘 (手动 CPU / 内存画布 / 词法AST台 / 产线与DrawVM)      │
│   ├─ 独立 Playground (在线编辑 / 本地单文件 / 本地 C 工程 三模式切换)           │

└────────────────────────┬─────────────────────────────────┬───────────────────┘

            │  crates/nmc-wasm (WASM) │       │  HTTP + WebSocket       │

                         │                    ┌────────────▼──────────────────────┐
                         │                    │  crates/nmc-bridge (本地轻量服务)   │

                         │                    │   ├─ 启动体检 (gcc/clang/make 指引) │

                         │                    │   ├─ C 工程识别 (nmc.project.json) │
```

### 双部署形态（同时支持）

1. **线上静态部署**：`web/dist` 部署在 GitHub Pages / Gitee Pages 等静态托管平台。零基础玩家打开网址即用 `nmc-wasm` 零安装开玩第 1~2 章；进入第 3 章后在本机启动 `nmc-bridge`，网页自动通过 `127.0.0.1:17320`（配置好 localhost CORS）连上本地工程。
2. **本地一体托管**：`nmc-bridge` 内置静态文件服务，玩家本地运行一条命令并打开 `http://127.0.0.1:17320` 即可离线游玩全部章节，无跨域问题。

## 3. 新增后端层：`nmc-wasm` 与 `nmc-bridge`

### 3.1 `crates/nmc-wasm`（浏览器内置引擎）

- 通过 `wasm-bindgen` 暴露 `run_code`、`submit_code`、`debug_start`、`debug_step`、`debug_step_back`、`debug_continue`、`debug_reset`、`compile_starlang_with_map`、`run_draw_vm`。
- 运行在浏览器 **Web Worker** 中，防止玩家代码死循环阻塞动画帧率。

### 3.2 `crates/nmc-bridge`（本地桥接服务）

基于 `axum` + `tokio` + `notify`，默认仅监听 `127.0.0.1:17320`（拒绝外部 IP 访问）。核心职责：

1. **启动环境体检**：启动时自动探测本机 `gcc` / `clang` / `make` 版本，向网页报告就绪状态；若缺失编译器，返回对应操作系统（Windows / macOS / Linux）的极简安装指引，不内置臃肿工具链，但在项目配置中支持自定义编译器路径。
2. **本地单文件监听模式（第 1~2 章可选）**：绑定本地某个目录或单个 `.s`/`.c` 文件；玩家在 VS Code 里按 `Ctrl+S`，Bridge 自动读取最新文件内容并通过 WebSocket 推送给网页 Playground，触发即时运行与沙盘动画。
3. **本地 C 工程模式（第 3~6 章主力）**：
   - 识别项目根目录的 `nmc.project.json`；
   - 监听 `src/`、`include/`、`Makefile` 文件变更（300ms 防抖），支持 Auto-Watch 保存即自动构建与跑测例；
   - 执行构建命令并流式推送编译日志；
   - 沙箱超时运行玩家编译出的可执行文件（默认单测例 2 秒上限 + 输出体积上限），捕获非零退出与崩溃信号（如段错误）翻译为人话提示；
   - 将产物送入 `DrawVM`（第 3 章）或 `riscv-assembler` + `riscv-simulator`（第 4~6 章）判定，并支持将任意失败测例装入调试会话供网页端单步/倒退回放。
4. **静态网页托管（可选）**：检测到本地前端产物目录时自动托管于 `http://127.0.0.1:17320`。
5. **进度同步**：与网页端无损合并同步 `~/.neomagiccompiler/user_progress.json`。

## 4. 本地项目规范与通信协议

### 4.1 项目识别文件：`nmc.project.json`

```json
{
  "schemaVersion": 1,
  "name": "my-c-compiler",
  "track": "chapter4",
  "mode": "c-project",
  "build": {
    "command": "gcc -Wall -Wextra -g src/*.c -o build/nmcc",
    "workingDir": ".",
    "timeoutMs": 15000
  },
  "executable": "build/nmcc",
  "watch": ["src", "include", "Makefile"]
}
```

对于第 1~2 章的本地单文件模式，可无需手写配置，直接启动 `nmc-bridge --watch-file ./level1_5.s`，或在网页端选择目标文件即可。

### 4.2 玩家编译器 CLI 契约

- **输入**：从 `stdin` 读取待编译的源程序文本。
- **正常输出**：向 `stdout` 打印目标产物（Token 流 / AST 文本 / `DrawVM` 指令流 / RISC-V 汇编文本），退出码 `0`。
- **错误输出**：语法或语义错误写入 `stderr`，返回非 `0` 退出码。
- **阶段参数（同一本地 C 工程贯穿多章的关键）**：支持 `--stage <lex|parse|sema|codegen>`，使同一个本地项目既能通过词法/语法关，也能跑通端到端代码生成关。

### 4.3 `nmc-bridge` HTTP + WebSocket 接口

所有 JSON 字段统一 `camelCase`，由共享契约测试约束前后端一致：

| 类别 | 接口 / 事件 | 说明 |
|------|-----------|------|
| 体检 | `GET /api/health` | 返回 Bridge 版本、本机 `gcc`/`clang`/`make` 检测结果、当前绑定模式与项目摘要 |
| 绑定 | `POST /api/project/select` | 切换本地 C 工程目录或本地单文件路径 |
| 脚手架 | `POST /api/project/init` | 在指定目录生成第 3/4 章 C 工程模板 |
| 构建 | `POST /api/project/build` | 触发本地 C 工程编译，返回成功状态与编译日志 |
| 运行 | `POST /api/level/:id/run` | 用默认测例跑一次（不计分，返回产物与快照/绘图轨迹） |
| 提交 | `POST /api/level/:id/submit` | 跑完该关全部测例（可先自动构建），返回 `SubmitDto`（含各测例 Diff 与失败现场） |
| 调试 | `POST /api/debug/start` / `step` / `step-back` / `continue` / `reset` / `quit` | 对指定测例（`caseIndex`）进行单步/倒退调试 |
| 实时流 | `WS /ws` | 推送 `file.changed`、`project.changed`、`build.log`、`test.progress`、`bridge.status` |

## 5. Web 前端、强交互沙盘与独立 Playground 架构（`web/`）

### 5.1 路由结构

| 路由 | 页面 | 核心能力 |
|------|------|---------|
| `/` | 关卡地图与技能树 | 6 章节点图、进度条、Bridge 状态灯、快捷进入独立 Playground |
| `/level/:id` | 关卡学习页 | 顶部 Before/After 目标卡；左栏：可玩沙盘引导 + 精简说明 + 3 级 Hint；右栏：嵌入式 Playground |
| `/playground` | **独立 Playground** | 顶栏切换 `在线编辑 / 本地单文件 / 本地 C 工程` + 测例选择器 + Watch 开关；主区统一承载代码/项目面板、实时沙盘画布、调试器与测例 Diff |
| `/wiki/:topic` | 概念图鉴 | 可交互速查卡：RV32IM 指令、C 语法、数据结构模板、`DrawVM` 指令集 |

### 5.2 四套数据驱动强游戏化沙盘组件（`web/src/sandboxes/`）

| 组件目录 | 核心交互能力 | 数据来源 |
|---------|------------|---------|
| `manual-cpu/` | 拖拽数值到寄存器/ALU/内存/栈，点击步进，并把手工操作**实时录制成等价 RISC-V 汇编** | 关卡 `meta.json` 的手工任务定义 + 模拟器 `StepPayload` |
| `memory-canvas/` | 2D 内存阵列、可拖拽指针箭头、结构体展开、链表/树连线、预测点击交互 + C↔汇编三联高亮 | `starlang` 行映射 + 模拟器内存快照 |
| `lexer-ast-lab/` | 字符传送带手动切词贴标签 + Token 卡片拖拽拼 AST 树 + 后序遍历指令吐出动画 | 关卡 `meta.json` 互动脚本 + 玩家编译器产出的 Token/AST |
| `pipeline-stage/` | 顶部通电流水线状态条 + 底部可切换视图（**`DrawVM` 实时 SVG/Canvas 绘图画布** / RISC-V 调试监视器 / 输出终端） | `DrawVM` 绘图轨迹数组 / `MachineSnapshot` / `SubmitDto` |

### 5.3 统一引擎抽象（`EngineClient`）

前端 UI 组件不直接依赖具体后端，全部通过 `EngineClient` 接口交互：
- `OnlineWasmClient`（Web Worker 中的 `nmc-wasm`）
- `LocalBridgeClient`（`127.0.0.1:17320` HTTP + WebSocket）

切换「在线编辑 / 本地单文件 / 本地 C 工程」只需替换当前 `EngineClient` 与代码源，**四套沙盘、单步/倒退调试器与 Diff 面板 100% 复用**。

## 6. 三道质量守门机制

1. **门一：关卡自检（`selfcheck`）**：用参考解（`.s`/`.c` 或参考 C 编译器工程）跑通该关全部测例。
2. **门二：关卡配置一致性检查**：校验元数据、初始代码、编辑器只读/提示行号、沙盘配置引用字段是否全部合法。
3. **门三：前后端 DTO 契约测试**：确保 `nmc-wasm` / `nmc-bridge` 与 `web/src/engine/types.ts` 字段完全一致。
