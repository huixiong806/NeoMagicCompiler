## 1. 五个 crate 与桌面壳

工作区成员在根 `Cargo.toml` 的 `members` 里登记，共 5 项：

```toml
members = [
    "app/src-tauri",             # 包名 neomagiccompiler（lib 名 neomagiccompiler_lib）
    "crates/neomagic-core",      # 包名 neomagic-core
    "crates/riscv-assembler",    # 包名 riscv-assembler
    "crates/riscv-simulator",    # 包名 riscv-simulator
    "crates/starlang",           # 包名 starlang
]
```

依赖方向是**单向**的，没有任何反向依赖、没有循环：

```
app/src-tauri ──→ neomagic-core ──┬─→ starlang ──────→ riscv-assembler ──→ riscv-simulator
                                  ├─→ riscv-assembler ─→ riscv-simulator
                                  └─→ riscv-simulator
```

（`starlang` 自己只产出汇编**文本**，不依赖汇编器；把文本交给汇编器是 `neomagic-core` 的 `runner` 干的。）

### 1.1 `crates/riscv-simulator` —— 魔导引擎（RV32IM 执行）

**职责**：只接受**机器码**，把它跑起来。不解析文本、不认识标签、不知道关卡是什么。

**边界（很重要）**：这一层是"硬件"，所以：
- 输入是 `&[u32]`（机器码字）与一份 `SimulatorConfig`；
- 输出是 `RunResult` / `StepResult`，即"机器现在是什么状态"；
- 它**不判断对错**。对错是判定器的事（见 1.5）。任何一个"这算不算通过"的问题都不该在这里回答。

| 文件 | 内容 |
|------|------|
| `src/lib.rs` | 公共导出；`reg_index` / `reg_name` / `reg_abi_name`（寄存器名 ↔ 索引，同时认 `x0`–`x31` 与 ABI 名） |
| `src/config.rs` | `SimulatorConfig`、`PauseOn`（7 个暂停开关）、`MmioMapping` / `MmioDirection`、`DEFAULT_RAM_SIZE = 0x1_0000` |
| `src/decode.rs` | `Instruction` 枚举与 `decode()`（RV32IM 全量 + `fence`/`ebreak`/`ecall`/`slp`） |
| `src/sim.rs` | `Simulator`：取指 → 解码 → 执行 → 写回；系统调用；暂停判定；`step` / `run` / `step_back` / `rewind_to` |
| `src/memory.rs` | 稀疏 RAM + MMIO（输入 FIFO / 输出 append-only 记录）+ 段错误 |
| `src/history.rs` | 环形历史缓冲（见 §7） |

关键 API（`pub use` 出来的）：`Simulator`、`SimulatorConfig`、`PauseOn`、`PauseReason`、
`RunResult`、`StepResult`、`StepBackResult`、`WordSize`、`ExecError`、`HistoryEntry`、
`MMIO_DISPLAY` / `MMIO_INPUT` / `MMIO_MANA`、`MEMORY_TOP`。

**内存映射**（`memory.rs` 的常量，`rebuild_machine` 里固定注册前三个）：

| 地址 | 方向 | 语义 |
|------|------|------|
| `0x00000000`–`0x0000FFFF` | RAM | 64 KiB，稀疏存储（`Vec<u8>` 实现，未写的读回 0） |
| `0xF0000000` | 输出 | 显示端口：写入低 8 位 = 输出一个字符 |
| `0xF0000004` | 输入 | 输入端口：读走队列里一个元素；队列空 → 返回 0 并置 `last_read_was_empty` |
| `0xF0000008` | 输入 | 魔力计：只读，返回已消耗周期数 |
| 其他 | — | 段错误（`MemError::SegFault`，变成 `PauseReason::Error`） |

**从输入端口读字符的宽度语义**（写关卡最容易踩的地方）：`read_word` / `read_half` 在**映射过的外设基地址**
上只取走**一个**队列元素并按低 8 位返回，不会顺带消费 `addr+1..3`。所以 `lw` / `lh` / `lbu` / `lb`
从输入端口读的效果完全一样（`memory.rs` 的 `mmio_input_word_read_consumes_exactly_one_element` 钉住）。

**系统调用**（`ecall`，调用号放 `a7` = `x17`）：

| `a7` | 语义 |
|------|------|
| `0` / `5` | 结束程序，退出码 = `a0`。**唯一会按 `pause_on.ecall` 暂停的 `ecall`** |
| `1` | 输出字符 `a0` 到显示端口 |
| `2` | 以十进制输出整数 `a0` |
| `3` | 读一个字符到 `a0`（队列空 → 0） |
| `4` | 读一个十进制整数到 `a0`（跳过空白，遇非数字停止） |
| `99` | 已消耗周期数 → `a0` |
| 其他 | 运行错误 |

其他 `ecall`（`putc` 等）**不暂停**，只是执行完继续跑。系统调用**只写 `a0`（`regs[10]`）**，
不碰任何 `t` 寄存器。

**暂停**：`PauseOn` 的 7 个开关决定"执行到什么事停下来"，`PauseReason::kind()` 给出稳定字符串
（`exit` / `ebreak` / `sleep` / `mmio_read_empty` / `mmio_write` / `error` / `limit`），
这个字符串**直接进 IPC**（`MachineSnapshot.pauseKind`），所以不要随意改。

- `PauseOn::debug()`：`ebreak` + 空读 + MMIO 写 + `slp` 都停（调试档，让"一步"是玩家能理解的一步）；
- `PauseOn::batch()`：只留 `ecall` 与 `error` / `limit`（判定档，快）。

`reset()` **保留 MMIO 输入队列与输出记录** —— 它们属于"外部世界"，不属于 CPU。

### 1.2 `crates/riscv-assembler` —— 星之语汇编器

**职责**：星之语**文本 → 机器码**。纯函数、无 IO、无全局状态。

**边界**：它认识标签、伪指令、指示符、表达式，但**不认识关卡**。白名单与禁止寄存器是通过
`Options` 传进来的（从哪来由上层决定），它只负责"不符合就报错，带行号"。

| 文件 | 内容 |
|------|------|
| `src/lib.rs` | `assemble()` / `assemble_with()`、`Assembly`、`AsmError`、`Options`、第一遍布局 `Layout` |
| `src/token.rs` | 词法切分 |
| `src/ast.rs` | `Item` / `Directive` / `Expr`、解析与表达式求值 |
| `src/encode.rs` | `OP_TABLE`、`is_pseudo` / `pseudo_requires` / `size_of` / `encode` |
| `src/tests.rs` | 汇编器测试（含"跳转真的跳对方向"的语义级回归） |

**两遍扫描**：
- **第一遍**按"条目长度表"推进地址计数器，收集标签地址与 `.equ` 常量。
  每条指令的长度只取决于助记符与操作数的**形式**（`li` / `la` 固定展开成 **2 条**：`lui` + `addi`），
  与标签的具体值无关 —— 所以两遍的地址完全一致，**不需要反复迭代**。
- **第二遍**真正编码，此时标签已全部就位。

**产物 `Assembly`**（这个结构是"引擎之间"的接口，值得记住）：

| 字段 | 含义 |
|------|------|
| `words` / `base_addr` | 代码段机器码（从 `base_addr` 起，`.org` 造成的空洞为 0） |
| `data` / `data_base` | 数据段字节（稀疏 `(地址, 值)`），没用过 `.data` 时 `data_base` 为 `None` |
| `source_map` | **指令地址 → 源行号**（1-based）。调试面板"现在执行到第几行"就靠它 |
| `symbols` | 标签地址表（函数模式靠它找目标函数） |

配套方法：`addr_to_line()` / `line_to_addr()`、`apply_to(&mut Simulator)`、
`initial_memory()`（给 `SimulatorConfig.initial_memory` 用的稀疏镜像）、`base_config()`（补齐 PC 与数据段）。

**支持范围**（`lib.rs` 的模块注释是权威清单）：RV32IM 全量指令、22 个伪指令
（`li la mv not neg nop j jr ret call beqz bnez blez bgez bltz bgtz bgt ble bgtu bleu seqz snez`）、
12 个指示符（`.text .data .org .word .half .byte .ascii .asciz/.string .space .align .equ/.set .globl`）、
表达式（十进制 / `0x` / 字符字面量 / 标签 / `.equ` 常量，`+ - * / % & | ^ << >> ~` 与括号）。

**白名单检查按助记符**：`Options.op_allowed()` 先看白名单里有没有这个助记符本身，
没有再（若 `allow_pseudo`）看它是伪指令、且**展开后用到的基础指令全在白名单里**。
所以关卡可以只写 `li`，也可以只写 `lui` + `addi`。

**错误**：`AsmError { line, message }`，`line == 0` 表示与具体行无关；`Display` 输出"第 N 行：<中文说明>"。

### 1.3 `crates/starlang` —— 星咒（C 子集）→ 星之语文本

**职责**：`&str` 星咒源码 → `CompileOutput { assembly, global_addrs }`。产物是**汇编文本**，不是机器码。

**边界（这条是刻意的）**：它**不依赖 `riscv-assembler`**。理由：产物要能在控制台原样展示给玩家看
（教学价值），而且"能不能汇编"是另一件事、由上层负责。

| 文件 | 内容 |
|------|------|
| `src/lexer.rs` | 词法（`Tok`、`Pos`） |
| `src/parser.rs` | 语法 → AST（`Program`、`Ty`） |
| `src/ast.rs` | AST 定义 |
| `src/codegen.rs` | 代码生成 + 运行时库；`DATA_BASE` / `STACK_TOP` / `MAX_ARGS` |
| `src/tests.rs` | 端到端测试（编译 → 汇编 → 真跑 → 校验结果） |

**运行时约定**（`codegen.rs` 模块注释是权威版本）：

| 项 | 约定 |
|----|------|
| 参数 | `a0`–`a5`，**最多 6 个**（`MAX_ARGS = 6`）；调用者把参数压在自己栈顶再 `jal` |
| 返回值 | `a0` |
| 帧指针 | `s0`；进函数后 `sp == s0`，局部变量与临时量都在 `s0` 之上 |
| 返回地址 | 存在 `s0 - 4`；旧 `s0` 存在 `s0 - 8` |
| 表达式求值 | 结果放 `a0`；需要两个操作数时左值压栈、右值算完弹到 `a1` |
| 数据段 | `DATA_BASE = 0x4000`（留 16 KB 给代码，离栈顶 `0xF000` 还有 44 KB 栈空间） |
| 栈顶 | `STACK_TOP = 0x0000_F000`，向下增长 |
| 入口 | `_start`：设 `sp`、初始化全局变量、`jal main`、`ecall` 退出 |

**不做寄存器分配、不做窥孔优化**（`codegen.rs` 里写了理由）：一切走 `a0`/`a1` 和栈，指令序列尽量直白，
因为玩家会读生成的汇编。

**内建函数**（运行时库自动产出）：`putchar` `getchar` `print_int` `print_str` `exit`。
**不支持**（给可读的中文错误而不是生成错代码）：浮点、`unsigned`、多维数组、函数指针、可变参数、
预处理指令、`switch` / `goto`。

`compile()` 返回 `CompileError { line, message }`；`check()` 只做检查不返回汇编（关卡预检用）。

### 1.4 `crates/neomagic-core` —— 领域层

**职责**：回答"游戏怎么玩"的全部问题：关卡怎么读、玩家代码怎么跑、怎么判过关、进度怎么存。

**边界**：**不依赖 Tauri**。所以它能脱离桌面壳被 `cargo test` 直接覆盖 ——
这是"关卡一定可解"能由测试守住的前提（见 §6）。

| 文件 | 内容 |
|------|------|
| `src/lib.rs` | 模块声明与 `pub use` 汇总 |
| `src/config.rs` | 测例 JSON → `LevelConfig`（宽容解析：扁平/嵌套写法都认） |
| `src/levels.rs` | 关卡三件套读取、`Content` 后端（磁盘 / 嵌入）、`parse_level_page`、`self_check` |
| `src/runner.rs` | 编译 → 装载 → 按测例跑；引导桩；`debug_simulator` |
| `src/judge/mod.rs` | 判定器：`judge()`、`check_case()`、`text_matches()`、`FailureReason`、`FailureSite` |
| `src/judge/scripted.rs` | 内置 Judge 注册表（4 个） |
| `src/progress.rs` | `user_progress.json` 读写（格式见 [`存档格式.md`](存档格式.md)） |
| `src/embedded.rs` | 编译期嵌入内容的读取入口 |
| `src/selfcheck.rs` | **关卡自检**（`#[cfg(test)]`，见 §6） |
| `build.rs` | 生成嵌入清单（见 §5） |

`pub use` 出来的公共 API：`LevelConfig` / `Goal` / `TestCase` / `CallSpec` / `MemExpect` / `Language`、
`judge` / `Verdict` / `TestVerdict` / `Diff` / `FailureReason` / `FailureSite`、
`LevelStore` / `LevelBundle` / `LevelSource` / `LevelError` / `EditorConfig`、
`UserProgress` / `LevelProgress` / `Settings`、
`Runner` / `CaseOutcome` / `CodeError` / `ErrorKind` / `MachineState`。

**运行器两种模式**（`runner.rs`）：
- **函数模式**（测例里有 `call`）：在 `BOOT_ADDR = 0x0800` 生成一小段引导代码
  （`li a0.., args` → `li t5, 目标` → `jalr ra, t5, 0` → `li a7, 0` / `ecall`），
  `a0` 就是返回值。
  > 引导桩**必须在 `0x0800`**：早期版本放在 `0x2000`，把关卡测例放在 `0x2000` 的数组整片盖掉了。
- **程序模式**（没有 `call`）：从入口开始跑，跑到 `ecall` 结束。

`DEFAULT_STACK_TOP = 0x0000_F000`。栈指针的处理有个刻意的细节：测例显式给了 `initial.sp` 就用它；
否则**只有当测例没有占用 `x2` 时才填默认栈顶** —— 第一章的关卡常把 x1/x2 当"两个格子"用，而 x2 恰好是 sp。
寄存器名统一规范化成 `xN` 再放进配置（`sp` 与 `x2` 是同一个寄存器，同时以两个键塞进去会因 HashMap
迭代顺序而不确定）。

`debug_simulator()` 造一台"停在起点、**已打开 `record_history`**、灌好输入"的机器给调试器用。
忘记打开历史记录会让"倒退"按钮静默无效（踩过一次：单步能用、倒退没反应）。

**判定器三条原则**（`judge/mod.rs` 模块注释）：只比测例写了的；输出文本按行规范化后比对
（去每行首尾空白、丢空行，所以缩进差异不算错、多输出一个数就算错）；失败必须给可读差异。
寄存器比对前先 `as i32`（否则 `-93` 会显示成 `4294967203`）。

**Judge 注册表**（`judge/scripted.rs` 的 `JUDGES`，4 个，全部是 Rust 函数、同进程）：

| 名字 | 参数 | 判定方式 |
|------|------|----------|
| `sort_check` | `arraySize` `maxValue` `memoryBase` `rounds` `seed` | 随机数组写进内存 → 玩家原地排序 → 校验内存真的有序 |
| `brackets_check` | `rounds` `maxLen` `seed` | 随机括号串 → 玩家输出 `1`/`0` |
| `expr_check` | `rounds` `maxOperands` `maxValue` `seed` | 随机表达式 → Rust 侧参考求值器算答案 → 比玩家输出 |
| `compile_and_run` | `program` `fn` `args` `expectedRet` | 跑玩家的编译器 → 把它的输出交给**真汇编器 + 真模拟器**执行 → 比返回值 |

新增 Judge 要改代码（这是"不要外部 EXE"的代价），但换来的是可单元测试、无额外进程。
自检里有一条 `judge_registry_is_wired_up`：关卡 json 里写了未注册的 judge 名会直接测试失败。

## 2. 桌面壳的三层分工

这是本项目**最关键的一条架构约定**，改动前请先读完这一节。

```
前端  window.__TAURI__.core.invoke('命令名', { camelCase 参数 })
  │
  ▼
lib.rs    IPC 层：只做参数转发与错误包装（`#[tauri::command]` 都写在这里）
  │        统一的 `fn ipc<T>(r: Result<T, ApiError>) -> Result<T, String>`
  ▼
api.rs    逻辑层：**不依赖 Tauri**，因此 cargo test 能直接调用
  │
  ▼
dto.rs    接口定义：与 compiler-content/frontend/src/core/types.ts 一一对应（全 camelCase）
  │
  ▼
neomagic-core → riscv-assembler / starlang / riscv-simulator
```

### 2.1 为什么业务逻辑**不能**写进 `#[tauri::command]`

Tauri 命令的入参是 `State<'_, T>`（例如 `State<'_, AppState>`），这个类型**在测试里造不出来** ——
没有 `AppHandle`、没有 Tauri 运行时。一旦逻辑写进命令函数，整条 IPC 链路就只能靠**手点游戏**验证。

所以现在的分工是：命令函数体只有一行 `ipc(state.xxx(...))`（或直接返回 `state.xxx()`），
`AppState` 上挂的是普通方法。`app/src-tauri/src/lib.rs` 末尾的 10 条集成测试
（`cargo test -p neomagiccompiler`）就是直接 `AppState::new(临时路径)` 然后调方法的，
覆盖：关卡列表 / 参考解走提交路径防回归 / 错误代码可读报错 / 答案错了要给差异与失败现场 /
单步-倒退-继续-重置 / 没进调试就单步报错 / 运行返回快照 / 存档往返 / 未知关卡不 panic。

**推论**：以后再加命令，照这个模板写 —— `lib.rs` 加一个转发 + `api.rs` 加一个方法 +
`dto.rs` 加类型 + `api.ts` 加一行 `invoke`，四边都要动。

### 2.2 三层的具体内容

| 层 | 文件 | 只做这些事 |
|----|------|-----------|
| IPC | `src/lib.rs` | `#[tauri::command]` 定义、`ipc()` 错误包装、`AppState` 的创建与 `manage`、`invoke_handler` 注册、`submit_code` 之后发 `submit-verdict` 事件 |
| 逻辑 | `src/api.rs` | `AppState`（关卡目录 + 存档 + 调试会话）、`ApiError`、快照构造、`dto` 转换 |
| 接口 | `src/dto.rs` | 全部 `Serialize`/`Deserialize` 结构，`#[serde(rename_all = "camelCase")]` |

`ApiError` 只是一句话字符串（`pub struct ApiError(pub String)`），`ipc()` 把它 `map_err(|e| e.0)` 成
`String` 交给 Tauri。为什么用 `.map_err` 而不是给 `ApiError` 加 `Serialize`：
让**错误形状在 IPC 边界上只有一个可能**（前端只需把这句话显示在控制台里）。

`AppState` 的字段：`store: LevelStore`、`progress: Mutex<UserProgress>`、`progress_path: PathBuf`、
`debug: Mutex<Option<DebugSession>>`。`DebugSession { sim: Simulator, runner: Runner }`
—— `runner` 留着是为了把 PC 翻译成源码行号。

`app/info` 里的 `contentRoot` 在嵌入内容后端下是字符串 `<嵌入内容>`（不是真路径）；
**拿它去读磁盘会读到空**，要正文请用 `LevelSource::page_text`。

### 2.3 前端一侧

`compiler-content/frontend/` 是 TypeScript + Lit + Vite 的编辑器前端，构建产物
（`theme/dist/riscv-playground.js` / `.css`）由 `book.toml` 的 `additional-js` / `additional-css`
注入每一页。

| 文件 | 职责 |
|------|------|
| `src/index.ts` | 入口：扫页面里的 `code.language-riscv`，解析后用 `<riscv-playground>` 替换掉那个 `<pre>` |
| `src/core/parser.ts` | 解析 ```` ```riscv ```` 块（JSON 头 + 单独一行 `---` + 代码），以及草稿 key 生成 |
| `src/core/api.ts` | **唯一**跟 Tauri 说话的地方；浏览器预览下抛 `NotDesktopError`（给一句人话提示，而不是 `undefined is not a function`） |
| `src/core/types.ts` | 与 `dto.rs` 对应的类型定义 |
| `src/core/constraints.ts` | 把后端的**区域**式约束（`readonlyPrefix/Suffix`）展开成行号/负行号，再应用到编辑器 |
| `src/core/storage.ts` | 草稿的 localStorage 读写与 500 ms 防抖 |
| `src/components/riscv-playground.ts` | 顶层容器：编辑器 / 工具栏 / 调试面板 / 控制台四个区域 + 所有动作的编排 |
| `src/components/editor.ts` / `toolbar.ts` / `debugger.ts` / `console.ts` | 四个区域 |

两个值得注意的实现事实：
- 编辑器是**一行一个 `<textarea>`**（这样才能做整行只读/隐藏/提示），不是单个大 textarea；
- 页面一加载，playground 会用 `load_level` 向后端要**权威的初始代码**覆盖页面里的那份
  （markdown 里的代码只是浏览器预览的后备），并顺手 `save_progress({ lastLevel })` 记一下位置。

`api.ts` 里目前有 14 个导出函数（13 个 `invoke` 包装 + `isDesktop`），但被 UI 实际调用的是 9 个：
`isDesktop` `loadLevel` `saveProgress` `runCode` `submitCode` `debugStart` `debugContinue`
`debugStep` `debugStepBack` `debugReset` `debugQuit`。**没有被调用的**：`listLevels`、`loadProgress`、
`appInfo`、`debugState` —— 它们是给侧边栏/关于对话框/会话重连预留的，后端命令是通的，
只是还没有 UI 用（`debug_state` 的用途是"前端刷新后重新接上会话"）。

## 3. 完整 IPC 命令表

来源：`app/src-tauri/src/lib.rs` 的 `invoke_handler`（15 条，按注册顺序）与 `dto.rs`。
前端调用见 `compiler-content/frontend/src/core/api.ts`。
**参数名在 JS 侧写 camelCase**（Tauri 会转成 Rust 的 snake_case）。

| # | 命令 | 参数 | 返回 | 一句话说明 |
|:-:|------|------|------|-----------|
| 1 | `greet` | `name: string` | `string` | 返回一句问候；预留给"帮助 / 关于"，当前无 UI 使用，**不参与游戏逻辑** |
| 2 | `app_info` | — | JSON 对象 | 诊断信息：`version` `levels` `contentRoot` `progressFile` `embeddedFiles` `stackTop` `bootAddr` |
| 3 | `list_levels` | — | `LevelSummary[]` | 全部关卡（含通关状态），按章节与关号排序；标题从关卡页的第一个 `## ` 行抠出来 |
| 4 | `load_level` | `level: string` | `LevelPayload` | 加载一关：编辑器配置 + 初始代码 + 参考解 + 是否已通过 |
| 5 | `run_code` | `level: string`, `code: string` | `MachineSnapshot` | **只跑不判定**，用该关第一条测例当场景；只看"它怎么跑" |
| 6 | `debug_start` | `level: string`, `code: string` | `MachineSnapshot` | 造一台停在起点、已开历史记录的机器，存进 `AppState` |
| 7 | `debug_step` | `n?: number` | `StepPayload` | 前进 n 步（默认 1）。一步 ≠ 一条指令，见下 |
| 8 | `debug_step_back` | `n?: number` | `StepPayload` | 倒退 n 步（默认 1），从历史恢复 |
| 9 | `debug_continue` | — | `MachineSnapshot` | 一直跑到下一个暂停点或程序结束 |
| 10 | `debug_reset` | — | `MachineSnapshot` | 机器回到起点、历史清空 |
| 11 | `debug_quit` | — | `void` | 退出调试模式（把会话扔掉） |
| 12 | `debug_state` | — | `MachineSnapshot \| null` | 当前调试快照（预留给"前端刷新后重连会话"，当前无 UI 使用） |
| 13 | `submit_code` | `req: { level, code }` | `SubmitDto` | 跑全部测例、判定、记进度；成功后**额外发 `submit-verdict` 事件** |
| 14 | `load_progress` | — | `UserProgress` | 读存档（内存里的那份） |
| 15 | `save_progress` | `patch?: { showHints?, lastLevel? }` | `UserProgress` | 写存档（`lastLevel` 只打日志不落盘） |

约定与陷阱：
- **第 13 条的参数是一个对象**（`SubmitRequest`），前端写 `invoke('submit_code', { level, code })`
  —— Tauri 会按名字把它塞进 `req` 字段；其余命令都是平铺参数。
- 出错时返回的都是**一句话字符串**（`ipc()` 包装的产物），前端拿到的永远是 `Error`。
- **"一步"不等于"一条指令"**：调试档把"会碰 MMIO 的指令"（读输入、写显示端口、`ecall`）也算作一步，
  因为它们会在执行**前**停下。所以契约是"前进 n 步再后退 n 步回到原样"，不是"tick 增加 n"。
  `StepPayload` 在 `MachineSnapshot` 之上多给 `regChanges` 与 `memChanges`（内存变化最多 64 条）。
- **`MachineSnapshot.pauseKind` 的取值来自 Rust 侧**：`ready`（还没开始）/ `exit` / `ebreak` / `sleep` /
  `mmio_read_empty` / `mmio_write` / `error` / `limit`。前端直接用它做分支，改 Rust 侧字符串会连带改前端。
- `submit_code` 的事件发送失败**不影响**判定结果（只 `eprintln!`）。

### 3.1 DTO 一览（`dto.rs`，全 camelCase）

| 类型 | 关键字段 |
|------|---------|
| `LevelSummary` | `id` `chapter` `number` `title` `language` `passed` `attempts` `bestScore?` |
| `LevelPayload` | `id` `title` `language` `editor` `initialCode` `solution?` `solved` |
| `MachineSnapshot` | `pc` `pcLine` `regs`（32 个，按 `xN` 键） `tick` `instructions` `output` `exitCode?` `pauseKind` `pauseDetail` `halted` `canStep` `canStepBack` |
| `StepPayload` | 上面全部 + `regChanges` + `memChanges`（`#[serde(flatten)]`，所以前端可以用 `extends`） |
| `SubmitDto` | `level` `passed` `score` `summary` `tests` `errors` `generatedAssembly?` `attempts` `firstClear` |
| `TestVerdictDto` | `name` `passed` `detail` `diffs` `actualOutput?` `failure?` |
| `DiffDto` | `what` `expected` `actual` |
| `FailureDto` | `caseIndex` `pc` `line` `reason`（机器可读） `reasonText`（给玩家） `regs` |
| `ErrorDto` | `line` `message` `kind`（`Assemble` / `Compile`） |
| `SubmitRequest`（入参） | `level` `code` |
| `ProgressPatch`（入参） | `showHints?` `lastLevel?` |

`EditorConfig` 与 `ToolbarConfig` 定义在 `neomagic-core/src/levels.rs`（带 `rename_all = "camelCase"`），
由 `LevelPayload.editor` 直接序列化给前端，所以它们也属于"IPC 接口"。

**改接口的规矩**：`dto.rs` 与 `types.ts` 是一对，没有代码生成，**两边必须一起改**。

## 4. 一次"提交"的完整数据流

以玩家按「提交」为例，把每一跳都写清楚：

```
1. mdBook 页面 app/src/cN_M.html
   页面里有个 <riscv-playground>（由 theme/dist/riscv-playground.js 的 index.ts 注入）
   config = riscv 块里的 JSON，initialCode = riscv 块里的代码
      │
2. riscv-playground.ts  _submit()
   code = editor.collectCode()          ← 从逐行 textarea 收集
      │
3. core/api.ts  submitCode(level, code)
   invoke('submit_code', { level, code })
      │  window.__TAURI__.core.invoke（withGlobalTauri: true）
      ▼
4. lib.rs  submit_code(app, state, req)
   dto = ipc(state.submit(&req.level, &req.code))?     ← 只有转发与错误包装
      │
5. api.rs  AppState::submit(level, code)
   bundle = store.load(level)          → levels.rs 读关卡页 + 测例 + 参考解
   verdict = neomagic_core::judge(&bundle.config, code)
   progress.record(...) + progress.save(progress_path)
      │
6. judge/mod.rs  judge(config, code)
   Runner::new(config, code)           → 星咒关先 starlang::compile() 得汇编文本
                                       → riscv_assembler::assemble_with(文本, Options{白名单…})
   逐条测例 runner.run_case(case)      → riscv_simulator 装载并 run()
   check_case(...)                     → 与 expected.* 比对，产出 diffs 与 failure_site
      │
7. 回到 lib.rs：app.emit("submit-verdict", &dto)
8. 回到前端：_renderVerdict() 把 summary / diffs / 失败现场写进控制台
```

**关键点**：整条链路上只有第 4 步碰 Tauri。第 5~6 步全是普通 Rust 函数，
所以可以被 `cargo test -p neomagiccompiler` 与 `cargo test -p neomagic-core` 覆盖。

**"运行"与"调试"走的是另一条岔路**：`run_code` 用 `default_case()`
（`Goal::Static`/`Output` 取第一条测例；`Goal::Scripted` 造一条空场景）跑一遍就返回快照，不判定；
`debug_start` 用同一个默认场景但改成 `PauseOn::debug()` + `record_history`，
把机器留存在 `AppState.debug` 里，之后每一次"单步"都是一次 IPC 往返。

## 5. 内容管线：关卡文件怎么变成游戏内容

### 5.1 关卡三件套

| 文件 | 内容 |
|------|------|
| `compiler-content/src/cN_M.md` | 关卡页：叙事 + 一个 ```` ```riscv ```` 块（JSON 配置 / 单独一行 `---` / 初始代码） |
| `compiler-content/src/tests/cN_M.json` | 测例与判定配置 |
| `compiler-content/solutions/cN_M.s` 或 `.c` | 参考解（扩展名由 `language` 决定：`asm` → `.s`，`c` → `.c`） |

命名约定：**不补零**（`c1_1.md`，不是 `c1_01.md`）。`SUMMARY.md` 里另有一页 `cN.md` 作章节首页
（例如 `c1.md`），它**不是关卡**：`parse_level_file_name` 要求文件名里既有 `c` 前缀又有 `_`，
所以 `c1.md` 不会被当成关卡。四章共 53 关 = 15 + 14 + 12 + 12。

`levels.rs` 的 `level_files()` 有一条重要的实现细节：它保留**文件名里的原始数字串**
（`c3_01.md` → `("3", "01")`），拼测例路径时用原始串。早期版本把 `01` 归一成 `1` 再拼 `c3_1.json`，
于是带前导零的关卡在嵌入内容后端里整批消失。

一关要被认出来，必须**关卡页与测例同时存在**（`found.retain(...)` 检查 `src/tests/cN_M.json` 在不在）。

**53 关的实际构成**（`compiler-content/src/tests/` 统计）：`language` 是 39 关 `asm` + 14 关 `c`
（`c` 全部在第二章）；`goal.type` 是 51 关 `static` + 2 关 `scripted`（4-11、4-12，都用 `compile_and_run`）；
**没有一关用 `output`**（该判定类型在代码里实现并有测试，只是内容层没用上）。

### 5.2 两个内容后端

`LevelStore` 内部是一个 `Content` 枚举，上层完全看不出来：

| 后端 | 构造 | 读什么 |
|------|------|--------|
| `Content::Dir` | `LevelStore::new(目录)` / `from_repo_root()` / `default_repo()` | 磁盘上的 `compiler-content/` |
| `Content::Embedded` | `LevelStore::embedded()` | 编译期嵌进二进制的字节 |

`LevelStore::prefer_repo_or_embedded()` 是**桌面壳实际用的那个**：先 `default_repo()` 看
`compiler-content/src` 在不在，在就用磁盘、不在就用嵌入内容。
这条"先盘后嵌"的顺序是刻意的：作者改完关卡刷新就能看到，不用重新编译 Rust。

### 5.3 `build.rs`：内容怎么进二进制

`crates/neomagic-core/build.rs` 递归收集 `compiler-content/src/` 与 `compiler-content/solutions/`，
把**仓库根的上一级**推出来定位 `compiler-content`，然后在 `OUT_DIR` 生成
`embedded_manifest.rs`：

```rust
pub static FILES: &[(&str, &[u8])] = &[
    ("solutions/c1_1.s", &[...]),
    ("src/c1_1.md", &[...]),
    ...
];
```

- 键是**相对 `compiler-content/` 的路径**，必须带 `src/` 或 `solutions/` 前缀 ——
  读取端用的就是 `src/c1_1.md` 这种路径。早期版本这里只写文件名，于是嵌入后端一个文件都查不到
  （而当时守卫测试因为特性默认关闭从没跑过，谁都没发现）。
- 用**字节字面量**而不是字符串字面量（内容里有中文，按字节嵌最省事）。
- 同时把 `build.rs` 自己、`compiler-content/` 目录、每个收集到的文件都登记成
  `cargo:rerun-if-changed` —— 否则改完关卡、`cargo run` 却还是旧内容，非常难查。
- 没有引入 `include_dir` 之类的新依赖：需求只有"按相对路径取一段字节"，30 行构建脚本就够。

`src/embedded.rs` 提供 `read(rel)` / `paths()` / `count()`；没开特性时 `FILES` 是空数组。

### 5.4 `embedded-content` 特性**默认开着**，为什么

`crates/neomagic-core/Cargo.toml`：

```toml
[features]
default = ["embedded-content"]
embedded-content = []
```

理由很实在：如果它默认关闭，单独跑 `cargo test -p neomagic-core` 时嵌入清单是空的，
守卫测试 `embedded_content_matches_the_repository` 会"无内容可比"而**静默通过**；
只有跑 `cargo test --workspace`（桌面壳依赖 `neomagic-core` 时打开了这个特性）才会真的比一遍。
于是"这个测试到底有没有在跑"就取决于你怎么调 cargo —— 太容易自欺。

默认打开之后，两种跑法都会真的验证"嵌入内容与仓库一致"。
想做极简构建可以 `--no-default-features`（此时 `LevelStore::embedded()` 会 `assert!` 失败，
因为 `embedded-content` 没开，这是刻意的：让误用立刻炸掉而不是静默返回空内容）。

## 6. 两门验证机制（各自能抓什么、抓不住什么）

这个项目有**两道不同的门**，它们守的是不同的东西。**不要用一道门的绿灯推断另一道也绿。**

### 6.1 门一：关卡自检（`selfcheck`）

命令：

```powershell
cargo test -p neomagic-core selfcheck -- --nocapture
```

`levels.rs::LevelStore::self_check(id)` 做的事：加载这一关 → 拿它的**参考解**去跑
`judge(&config, solution)` → 返回 `Verdict`。`selfcheck.rs::check_all()` 对全部关卡跑一遍，
把"跑不过的"和"缺参考解的"分开报。

**它能抓住**：测例写错（期望值与参考解不符）、参考解写错、参考解与测例不匹配、
参考解根本编不过（星之语汇编错误 / 星咒编译错误）、程序死循环超限、运行时错误。
换句话说，"**这一关到底有没有解、我的参考解是不是真解**"。

**它抓不住**：编辑器约束（见 6.2）、叙事内容（错别字、术语）、按钮点下去有没有反应
（前端行为完全不在覆盖范围内）。**自检全绿 ≠ 关卡可玩。**

两个调试口子：

| 环境变量 | 命令 | 作用 |
|---------|------|------|
| `NMC_SELFCHECK=3-4,3-5` 或 `c3_4,c3_5` | `cargo test -p neomagic-core selfcheck_only -- --nocapture` | **只**自检列出的关卡。给并行写关卡的作者用（别让别人的关卡分散注意力）；未设置时这条测试直接 return（不失败） |
| `NMC_SELFCHECK=4-4` + `NMC_SELFCHECK_VERBOSE=1` | `cargo test -p neomagic-core selfcheck_verbose -- --nocapture` | **逐条测例**打印"输入 / 期望 / 实际"。默认的 `summary` 只报**第一条**失败测例 |
| — | `cargo test -p neomagic-core every_level_is_solvable_with_its_reference_solution` | 全量自检（`check_all` 的测试入口，等价于上面第一条） |

`selfcheck_verbose` 为什么要存在（真事）：某关的自检汇总只报第一条失败测例，
于是**另外三个 bug 加一条写错的期望值**被一起藏住了，修掉第一条才露出第二条，来回好几轮。
**作者调试某几关时应该用 verbose，不要只看 summary。**

`selfcheck_verbose` 对 `Goal::Scripted` 关卡**不会逐例展开**（judge 自己生成输入），
它会打印一行说明并把这关算作"待看"，要用 `self_check` 看结论。

### 6.2 门二：关卡文件一致性 + 编辑器约束行号检查

命令：

```powershell
cargo test -p neomagic-core every_level_page_and_test_config_are_consistent
```

它对每一关检查：

1. **关卡页与测例的 `language` 一致**（`EditorConfig.language == LevelConfig.language`）；
2. 关卡页**有初始代码**（不能是空白）；
3. 关卡页里的 `level` 字段与文件名对得上；
4. **编辑器约束的行号有意义**（`check_editor_constraints`）：
   - `readonlyPrefix` / `readonlySuffix` 不能大于初始代码总行数
     （前端把它当"把前 N 行设只读"，`N > 行数` 就会**整篇锁死**，玩家一个字都改不了）；
   - `readonlyPrefix + readonlySuffix` 不能覆盖全部行（那样玩家没有任何可改的地方）；
   - `hidden` / `highlight` 的行号必须在 `1..=总行数` 内；
   - `suggested` 的键必须在 `1..=总行数` 内（否则提示指不到任何一行）。

**这条门为什么必须单独存在**：约束写错时**自检照样全绿** —— 因为自检只把参考解喂给判定器，
**根本不经过编辑器**。真实事故：某关 `readonlyPrefix: 119` 而初始代码 300+ 行，
前端把每一行都锁住，关卡直接不可玩，而所有测试都是绿的；
第四章有三关的 `suggested` 键写的是 **Markdown 行号**而不是**代码行号**，13 条提示指不到任何一行。

**它抓不住**：行号合法但**语义**写错（比如把第 3 行的提示写在第 4 行上）、
隐藏行把关键代码藏起来、只读区域锁住了玩家真正要改的那几行 —— 这些只能靠人工试玩。

### 6.3 其他守门测试（同一个文件里）

| 测试 | 守什么 |
|------|--------|
| `embedded_content_matches_the_repository` | 嵌入内容与仓库逐关一致：关卡列表、初始代码、参考解、`level`、判定配置。**只在 `embedded-content` 打开时编译**（默认打开，见 §5.4） |
| `judge_registry_is_wired_up` | 关卡 json 里写的 `judge` 名字必须在 `JUDGES` 里有；写了未注册的 judge 会直接失败 |

### 6.4 门与命令的对应关系

| 命令 | 门一 | 门二 | 其他 |
|------|:---:|:---:|:---:|
| `cargo test -p neomagic-core selfcheck -- --nocapture` | ✅ | | |
| `cargo test -p neomagic-core every_level_page_and_test_config_are_consistent` | | ✅ | |
| `make book-test` | ✅ | ✅ | 先 `mdbook build`（含前端构建） |
| `make test` | ✅ | ✅ | + `cargo test --workspace`（引擎、IPC 全部） |
| `cargo test --workspace` | ✅ | ✅ | 全绿才算"内容与代码都过" |

## 7. 历史回溯的设计（倒退按钮凭什么能退）

`crates/riscv-simulator/src/history.rs`。核心决定是**记录"被覆盖的旧值"，而不是快照整个机器**。

- 一条 `HistoryEntry` 存：`tick`（指令序号，从 1 开始）、`old_pc`、
  `old_reg: Option<(u8, u32)>`（被覆盖的寄存器索引与旧值）、
  `old_mem: Option<(u32, u8)>`（被写掉的字节地址与旧值）。
- **99% 的指令只改 1 个寄存器 + PC**，所以一条记录很轻（几十字节），
  两万条也在百 KB 量级 —— 这就是不存全量快照的原因。
- 容量满后**环形淘汰最老记录**；`base_tick` 记下"已被淘汰的最后一个 tick"，
  也就是**最老可回退点**（`entries` 的第一条对应 `base_tick + 1`）。
- 默认容量 `history_capacity = 20_000`，但 `record_history` 默认为 `false`；
  只有调试会话会打开它（`Runner::debug_simulator`）。**这个开关不打开，"倒退"会静默无效。**

两个倒退入口（`sim.rs`）：

| 方法 | 语义 |
|------|------|
| `step_back(n)` | 倒退 n 条；目标是 `tick - n`，但被 `base_tick` 夹住（退不到比最老可回退点更早） |
| `rewind_to(tick)` | 回到指定 tick（含）；同样被 `base_tick` 夹住 |

两者都收敛到内部的 `undo_to(target)`：从历史尾部逐条弹出，写回 `old_pc` / `old_reg` / `old_mem`，
同时把每个被恢复的值收进 `StepBackResult.reg_changes` / `.mem_changes`（前端拿它做闪烁提示）。
倒退结束后会**清掉 `halted` / `exit_code` / `last_pause` 并重新置 `running = true`** ——
所以"程序已经结束"之后再点倒退、然后再点继续，是能接着跑的。

`reset()` 会**重建**历史（`History::new(0)` 或按配置容量），`tick` 归 0；
`base_tick` 随 `rewind_to` 一起推进（`pop_until` 会同步更新 `base_tick`）。
`Simulator::history_base_tick()` 暴露给上层，`api.rs` 用它算 `canStepBack = tick > base_tick`。

## 8. 为什么不用 `mdbook test`

`mdbook test` 只会把**没标语言**的代码块当 **Rust** 去编译。而关卡页里的代码块是
星之语汇编、token 序列、伪代码这类自定义文本，于是几十处都会报
`cannot find value` / `undeclared type` —— 这些报错没有任何意义，它们只是"这段汇编不是 Rust"。

所以 `Makefile` 的 `book-test` 目标**故意不调用 `mdbook test`**，而是换成两件事：

```make
book-test: book-build
	cargo test -p neomagic-core selfcheck -- --nocapture
	cargo test -p neomagic-core every_level_page_and_test_config_are_consistent
```

`make book-test` 检查的是**这个项目自己的东西**（关卡可解 + 关卡文件一致），而不是 Rust 代码块。
Rust 代码本身的守门人是 `cargo test --workspace`（那一堆 `#[cfg(test)]` 与 crates 内的测试模块）。

## 9. 文档与实现的已知差异（别照旧文档抄）

以下都是核对代码时发现的、容易被旧文档带错的地方：

| 位置 | 旧文档怎么说 | 代码实际是 |
|------|-------------|-----------|
| `总设计.md` §3.2 | 星咒编译产物"数据段从 `0x0100`" | `starlang::DATA_BASE = 0x4000`（放 `0x0100` 时程序一长就撞上数据，已改） |
| `总设计.md` §3.2 | 内存布局 "`0x0000`–`0x00FF` 保留给运行时引导代码" | 引导桩在 `BOOT_ADDR = 0x0800`；`0x0000`–`0x00FF` 没有特殊含义 |
| `总设计.md` §4 | 星咒函数"最多 8 个整型参数" | `starlang::codegen::MAX_ARGS = 6`（`a0`–`a5`） |
| `总设计.md` §5.1 | 有 `constraints.lockedRegion` 字段 | 后端**不解析**这个字段（`levels.rs::parse_level_page` 只认 `readonlyPrefix` / `readonlySuffix` / `hidden` / `highlight` / `suggested`） |
| `总设计.md` §5.2 | `initial.memory.strings`（`{"0x1000": "hello"}` 直接给字符串） | 字符串要写成 `{"string": "hello"}`（`MemExpect::String`），顶层没有 `strings` 这个键 |
| `总设计.md` §5.4 | `static` 判定比对 `output.mmio` | `static` 比 `output.text`（字符串）；没有 `output.mmio` 这个字段 |
| `总设计.md` §7 | `sort_check` 参数含 `max_value` | 实际是 camelCase：`arraySize` `maxValue` `memoryBase` `rounds` `seed` |
| `总设计.md` §7 | `compile_and_run` 参数 `program` `fn` `args` `expected_ret` | 实际是 `program` `fn` `args` `expectedRet` |
| `总设计.md` §9 | "星咒编译器内部以线性 IR 指令列表（`crates/starlang/src/ir.rs`）为中间层" | **没有 `ir.rs`**：parser 直接产出 AST，`codegen.rs` 从 AST 生成汇编文本，没有独立 IR 层 |
| `总设计.md` §9 | "`Simulator` 已支持完整 RV32IM，第五章可以直接复用" | 一致 |
| `术语表.md` 附录 A | 关卡文件名 `c{章}_{关}.md`（不补零） | 一致；但 `levels.rs` 实际上**也接受**带前导零的名字（保留原始串），只是全仓现在都按不补零写 |
| 本文件 §2.3 之外的旧接口文档 | 已有 15 条命令里的 `greet` 被算进"游戏命令" | `greet` 不参与游戏逻辑，`submit-verdict` 事件也没有 UI 监听（前端目前直接渲染返回值） |
| `README.md` / `总设计.md` | 4 个内置 Judge 看起来都在用 | **实际只有 `compile_and_run` 被关卡用到**（4-11、4-12）。`sort_check` / `brackets_check` / `expr_check` 只有单元测试在用，53 关里没有一关配置它们 |
| `总设计.md` §5.4 / §6.2 | 多处写"输出判定"/`goal.type = "output"` | **53 关里一条 `"type": "output"` 都没有**：51 关 `static` + 2 关 `scripted`。`Goal::Output` 的实现与测试都在（`judge` 里走 `output_only` 分支），只是没有关卡用它 |
