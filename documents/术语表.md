# 术语表

本文档统一定义 Neo Magic Compiler 中跨文档使用的核心术语。
**术语以本表为准**；架构从何而来见 [`架构.md`](架构.md)（实现现状）与 [`总设计.md`](总设计.md)（冻结的设计与大纲）。
早期设计文档曾在本文附录 B 列过清单，**已经全部归档删除**，见那一节。

---

## 一、世界观词汇（写关卡时必须用这套说法）

| 系统概念 | 魔法说法 | 何时用真实说法 |
|----------|----------|---------------|
| 计算机 | **魔导核心** | 讲底层硬件时可用"核心" |
| 处理器 | **魔导引擎** | 讲取指/执行时可用"引擎" |
| 存储器 | **记忆晶阵** | 讲地址/宽度时**必须**说"内存" |
| 指令 | **星之印** | 讲具体指令时**必须**写真实助记符（`add`/`lw`） |
| 汇编语言 | **星之语**（低阶语） | 关卡页里两可，代码块一律是真实汇编 |
| C 子集高级语言 | **星咒**（高阶语） | 同上 |
| 周期消耗 | **魔力消耗** | 讲性能时 |

寄存器、函数、栈、地址、指针这些术语**照常用真实说法**——魔法外皮是为了好记，不是为了遮掩概念。

## 二、两门语言（本项目最容易搞混的地方）

| 名字 | 是什么 | 谁写它 | 工具链 |
|------|--------|--------|--------|
| **星之语** | 汇编（RV32IM + 少数自定义指令） | 玩家（第一、三、四章） | `crates/riscv-assembler` |
| **星咒** | C 子集高级语言 | 玩家（第二章） | `crates/starlang` |

- Rust crate 名叫 `starlang`（历史原因），指的就是**星咒**编译器。
- 第四章的产物是**星之语**：玩家的编译器把星咒源码翻译成星之语文本，
  再由本项目的汇编器 + 模拟器真的跑起来。

## 三、关卡与内容

| 术语 | 标识符 / 位置 | 说明 |
|------|--------------|------|
| 关卡 | `level`，ID 形如 `"1-5"` | 基本教学单元 |
| 关卡三件套 | `src/cN_M.md` / `src/tests/cN_M.json` / `solutions/cN_M.s\|.c` | 缺一不可 |
| 关卡页 | `cN_M.md` | 叙事 + ```` ```riscv ```` 块（编辑器配置 `---` 初始代码） |
| 测例 | `tests/cN_M.json` | 判定配置：`availableOps` / `forbiddenRegs` / `maxInstructions` / `goal` |
| 参考解 | `solutions/cN_M.*` | 作者写的标准答案；**关卡自检**用它证明关卡可解 |
| 可用指令 | `availableOps` | 本关允许的助记符白名单；`[]` = 全开 |
| 禁止寄存器 | `forbiddenRegs` | 本关禁止访问的寄存器 |
| 判定目标 | `goal.type` | `static`（比状态） / `output`（只比输出与退出码） / `scripted`（内置 judge） |
| 内置 judge | `sort_check` / `brackets_check` / `expr_check` / `compile_and_run` | Rust 侧随机或多轮判定，不依赖外部 EXE |
| 函数模式 | 测例里有 `call` | 设好 `sp`、把参数放 `a0..`、`jal` 进目标函数，比 `a0` |
| 程序模式 | 测例里没有 `call` | 从代码段入口跑，跑到 `ecall` 结束 |
| 输出比对 | —— | **规范化**：按行拆分 → 去首尾空白 → 丢空行 → 逐行完全一致 |
| 关卡自检 | `neomagic-core` 的 `selfcheck` | 用参考解跑全部测例；这是内容质量底线 |

## 四、编辑器与前端

| 术语 | 标识符 | 说明 |
|------|--------|------|
| 编辑器 | `createEditor`（`frontend/src/components/editor.ts`） | **一行一个 textarea**，这样才能做整行只读/隐藏/提示 |
| 行号列 | gutter | 左侧行号栏，与代码区同步滚动 |
| 只读行 | `constraints.readonlyPrefix/Suffix` | 用**区域**而非行号列表：玩家在中间插行也不会破坏锁定 |
| 隐藏行 | `constraints.hidden` | 玩家看不见，提交时代码原样保留 |
| 行内提示 | `constraints.suggested` | 行号 → 灰色占位文本 |
| 高亮行 | `constraints.highlight` | 行号列表，视觉强调 |
| 工具栏 | `createToolbar` | 运行 / 调试 / 提交 / 载入 / 保存；调试模式下切换成另一组按钮 |
| 控制台 | `createConsole` | 判定结果、输出、错误都显示在这里 |
| 《机器状态》面板 | `createDebugger` | PC 摘要 + 寄存器网格（8×4）+ 内存监视 |
| 草稿 | `level-{id}-draft`（localStorage） | 玩家未提交的代码，自动保存 |
| 进度 | `user_progress.json`（应用数据目录） | 通关状态、尝试次数、最高分 |

## 五、运行与调试

| 术语 | 标识符 | 说明 |
|------|--------|------|
| 模拟器 | `riscv_simulator::Simulator` | Rust 写的 RV32IM 执行引擎（**不是** C++ 子进程） |
| MMIO | `0xF0000000` 显示端口 / `0xF0000004` 输入端口 / `0xF0000008` 魔力计 | 读写外设就是读写内存地址 |
| 系统调用 | `ecall`，调用号在 `a7` | `0`/`5` 退出、`1` 输出字符、`2` 输出整数、`3` 读字符、`4` 读整数、`99` 读周期数 |
| 暂停条件 | `PauseOn` | `ebreak` / `ecall` / 空读输入 / 写显示端口 / 出错 / 超限 / `slp` |
| 单步 | `debug_step` | 推进到下一个暂停点；"一步"不一定等于"一条指令" |
| 倒退 | `debug_step_back` | 靠历史回溯实现；因此调试配置必须打开 `record_history` |
| 失败现场 | `FailureSite` | 测例失败时的 PC、行号、寄存器快照；前端据此自动进调试 |
| 机器快照 | `MachineSnapshot` | 一次运行/单步之后的 PC、寄存器、输出、暂停原因等 |

## 六、工程

| 术语 | 说明 |
|------|------|
| 领域层 | `crates/neomagic-core`：关卡加载 / 运行器 / 判定器 / 存档。**不依赖 Tauri**，可独立测试 |
| 逻辑层 | `app/src-tauri/src/api.rs`：IPC 的业务逻辑，同样不依赖 Tauri（便于测试） |
| 转发层 | `app/src-tauri/src/lib.rs` 的 `ipc` 模块：只做参数转发与错误包装 |
| 接口定义 | `app/src-tauri/src/dto.rs` ↔ `frontend/src/core/types.ts`，全 camelCase，两边一起改 |
| 嵌入内容 | `neomagic-core` 的 `embedded-content` 特性：关卡内容编译进二进制（**默认开启**，`--no-default-features` 可关） |
| 关卡自检 | `neomagic-core::selfcheck`（`cargo test -p neomagic-core selfcheck`）：用参考解跑全部测例 |
| 离线构建 | 根目录 `.cargo/config.toml` 的 `[net] offline = true` |
| IPC 命令 | 共 15 条，注册在 `app/src-tauri/src/lib.rs` 的 `invoke_handler`；完整表见 [`架构.md`](架构.md) §3 |
| `submit-verdict` | `submit_code` 判定完成后发的事件名（前端可监听做通关动画，目前还没有 UI 监听） |

## 附录 A：标识符命名约定

| 场景 | 约定 | 示例 |
|------|------|------|
| 关卡 ID | `{章}-{关}` | `"1-1"`、`"4-12"` |
| 关卡文件名 | `c{章}_{关}.md`（**不补零**） | `c3_4.md` |
| 寄存器名 | `x0`..`x31`（配置里也可用 ABI 名） | `"x3"`、`"sp"` |
| Tauri 命令名 | snake_case | `"run_code"`、`"debug_step"` |
| IPC JSON 字段 | camelCase | `"initialCode"`、`"pauseKind"` |
| 关卡 JSON 字段 | camelCase | `"availableOps"`、`"readonlyPrefix"` |
| 汇编标签 | `L` + 数字（生成代码）/ 有意义的名字（手写代码） | `L12`、`loop` |
