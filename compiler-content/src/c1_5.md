## 1.5 记忆晶阵：数住的地方

那面墙上钉着的徽记在暗处泛着很淡的光，每个徽记下面都压着一条细细的刻度，刻度旁边是一个地址。

"寄存器只有三十二格，而且它们就长在引擎身上。"星泠把手电的低光扫过墙面，"墙里不一样。墙里面是**记忆晶阵**，一格挨着一格，多到数不清。每个格子有一个地址，像门牌号。"

岩舟拿凿子背敲了一下墙面，声音很闷，像敲在一整块还没切开的石头上。"这么多格子，我怎么知道哪格装了什么。"

"你不需要知道全部，闸会告诉你地址。"星泠在墙面上点了一处刻度，那里浮出 `0x1000` 这个数，"这一格里面有一个数。闸要你把它读出来，放进 x5。"

她在旁边往下数了四格，点住第二处刻度：`0x2000`。

"然后，把 x1 里的数写到这里。"

"读一个，写一个。"岩舟把凿子收回去，"读了放哪儿？"

"你指定一个寄存器。"星泠说，"读和写各有一条指令："

```text
lw  目标寄存器, 偏移(基址寄存器)   # 从内存读一个 32 位的数进寄存器
sw  源寄存器, 偏移(基址寄存器)     # 把寄存器里的数写进内存
```

"括号外面那个偏移是'从基址往后数几个字'。前面的 `li x1, 0x2000` 是给你的脚手架：x1 里已经是 `0x2000` 这个地址，所以写回的时候用 `0(x1)` 就正好落在那一格上。"

"那读 0x1000 呢？"

"同一件事，换个地址。"星泠说，"这也是这一关第一次出现'一个数代表一个地址'——x1 里装的是门牌号，不是内容。读和写的括号里，永远填地址。"

```riscv
{
  "level": "1-5",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 1,
    "readonlySuffix": 1,
    "suggested": { "2": "li x5, 0x1000" }
  }
}
---
li x1, 0x2000
# 第一步：把 0x1000 那一格里的数读进 x5
# 第二步：把 x1 里的数（就是 0x2000 这个地址值）写进 0x2000 那一格
ecall
```

写完别急，先在面板里看一眼 x5——它应该是 `0x1000` 里原本躺着的那个数。这一关有一个陷阱值得你想一想：**x1 里现在装的是地址，不是数据**。写进 0x2000 的，就是 `0x2000` 这个门牌号本身。闸要的正是它。

墙面深处传来一声很轻的滑动声，像有谁把一叠牌子推回了原位。星泠把手电移向石阶更下面——那里还有一排刻度，一直排到看不见的暗处。

"一格里一个数，读起来还算省事。"岩舟说，"要是它们排成一整排呢？"
