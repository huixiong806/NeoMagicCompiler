## 4.6 形对了，意不一定对

石板上最后那行刻痕，岩舟念了两遍。

```
int a; int b; int a; print c;
```

"每一句我都认识。"他说，"`int a;` 是'这里有一块叫 a 的格子'，`print c;` 是'把 c 念出来'。语法上……好像没错。"

"语法上确实没错。"星泠说，"`int 名字;` 和 `print 名字;` 这两种句子，我们这两关写的解析器都能一口吞下去，连眉头都不皱一下。**这就是问题**。"

她伸出两根手指。

"可是如果你真的让魔导核心去执行这一段，它会在两处打滑：第一处，`int a;` 出现了**两次**——第二块 `a` 的格子该放在哪儿？原来的 `a` 怎么办？第二处，`print c;` 里的 `c`——**它根本不存在**。谁也没声明过它。"

岩舟把这两处点了一下："那这不是'读不懂'，是'读懂了但不合理'。"

"对。这一步有个正式的名字：**语义分析**。前面两关做的叫**语法分析**——它的任务是回答'这句话**长得**对不对'；语义分析要回答的是'这句话**说得**对不对'。分开的理由很实在：语法分析只看**形状**，而形状是有限的、可以用递归下降穷举的；语义分析要看**含义**，它得记住'到目前为止这个世界里有哪些名字'。"

"所以我们需要一个……账本？"

"一个账本。"星泠从石缝里取出一块巴掌大的薄石片，石片上刻着 `a` 到 `z` 一共 26 个小格，"变量名只准用单个小写字母，所以账本刚好 26 格。每格记一件事：这个名字**有没有被登记过**。"

她指着石板：

```text
int a;     →  a 那一格还是空的 → 登记 a
int b;     →  b 那一格还是空的 → 登记 b
int a;     →  a 那一格已经有名字了 → 重复声明，报 ERR:dup:a
print c;   →  c 那一格是空的 → 用了没声明的名字，报 ERR:undecl:c
```

"这台机器的工作方式，跟前面两关**完全不一样**，"星泠强调，"前面两关是一层套一层的递归（表达式里面套表达式）。这一关没有嵌套——它就是**一句话一句话地往下走**，每走一句，往账本上记一笔或者查一笔。**一条直线 + 一个账本**，就够了。"

岩舟拿起刻笔，忽然停住："报错之后呢？要停下来吗？"

"不要停。"星泠说，"真正的编译器不会在第一个错误上就死掉——那样你改一个错、重跑一次、又看到下一个错，能烦死。它会**一路查到底**，把所有错都报给你。所以："

- 每遇到一条语句，就查一次、记一次；
- 有错就报一行，然后**继续往下走**；
- 没错的语句，**什么也不输出**。

"最后一条你要特别注意：如果整段程序干干净净，**这块石板就一个字都不会亮**。没有输出，不是你没做出来——那就是正确结果。"

岩舟照着做了。他先写下 `int a;`，账本上 `a` 那格亮起一个小点；再写 `int b;`，`b` 那格也亮；写到第三个 `int a;` 时，石板上浮出一行暗红色的字：

```
ERR:dup:a
```

紧接着第四句 `print c;`，又浮出一行：

```
ERR:undecl:c
```

两行字浮在石板上，谁也没动手擦。过了好一会儿，岩舟才说：

"我忽然明白这两关连起来是什么了。"

"说说看。"

"上一关我们把表达式写成了一棵树——那是'它长什么样'。这一关我们给它加了一个账本——那是'它是什么意思'。"他顿了顿，"再往下，就不只是**检查**了。再往下……我们该**生成**点什么了吧？"

星泠抬头看了他一眼，没接话。她把那块薄石片翻过来，背面刻着一行列规范得不像古物的字：

```
addi t0, t1, 0
```

"下一关，"她说，"让你的编译器**自己写下星之印**。"

---

**本关任务**：读入一段只有 `int 名字;` 和 `print 名字;` 两种语句的极简程序，检查**重复声明**与**未声明就使用**，按遇到顺序报出错误码。

### 输入与输出格式（4.6）

**输入**：一段极简程序，只含这两种语句：

```text
int 名字;        ← 声明
print 名字;      ← 使用
```

- 每条语句都由 `关键字 名字 ;` 三段拼成；语句之间可以只用空格隔开，也可以换行；行尾有 `\n`（值 10）。
- **变量名限定为单个小写字母 `a`–`z`**（`int a;`、`print q;`），不会出现 `aa`、`x1`、`_t` 这种。
- 程序从 `0xF0000004` **按字节**读字符，读到 `0` 表示输入结束。空格、`\n`、`\r` **当成语句分隔符跳过**。
- 首尾可能有空白，也可能整段是空的。

**检查规则（按句子从左往右走一遍）**：

1. 遇到 `int 名字;`
   - 这个名字**已经登记过** → 输出一行 `ERR:dup:名字`
   - 否则 → 把它登记进账本
2. 遇到 `print 名字;`
   - 这个名字**没有登记过** → 输出一行 `ERR:undecl:名字`
   - 否则 → 什么也不输出

**输出**：

- 错误**按遇到的顺序**一行一个，格式是 `ERR:dup:x` / `ERR:undecl:x`（冒号后面就是那个字母本身，如 `ERR:undecl:c`）。
- 检查通过的语句**不输出任何东西**。
- **全部合法 ⇒ 程序不产生任何输出**（判定里的期望输出就是空串）。

| 输入 | 输出 |
|------|------|
| `int a; int b; int a; print c;` | `ERR:dup:a`<br>`ERR:undecl:c` |
| `int a; print a;` | （空） |
| `print a;` | `ERR:undecl:a` |
| `int a; int a; int a;` | `ERR:dup:a`<br>`ERR:dup:a` |
| `print z; print y;` | `ERR:undecl:z`<br>`ERR:undecl:y` |

注意 `int a; int a;` 那条：第二次 `int a;` 报错，但 `a` **仍然是已声明的**（账本上那一格早就有了），所以后面再 `int a;` 还是报 `dup`，而 `print a;` 永远不会报 `undecl`。

判定时输出按行比对（去首尾空白、丢空行），所以"空输出"就是**一行都没有**。

```riscv
{
  "level": "4-6",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 4,
    "suggested": {
      "13": "接下来要写的是：j scan_loop 一圈读一条语句、走完就收工；结束用 li a7, 0 + ecall",
      "14": "每一圈：读一个非空字符（先看回退槽 a2，再看 0xF0000004；读到 0 就是输入结束）→ 跳过空格 / '\\n' / '\\r' → 判断 'i'(int) 还是 'p'(print) 并读掉剩下的字母 → 读变量名（'a' 减到 0..25）→ 吃掉 ';' → 查账本 → 回到循环开头。⚠️ 报错时要印出来的是**变量名**，所以名字必须在「吃掉 ';'」**之前**搬到别的寄存器（'吃掉 ;' 会把当前字符换成 ';'，直接印它就会得到 ERR:undecl:;）。账本用 0x3000 起 26 个字节，第 (字母-'a') 格非 0 表示已声明"
    }
  }
}
---
# 入口：把账本（0x3000 起 26 个字节）清零
li   t6, 0x3000
li   t5, 26
li   t4, 0
zero_loop:
sb   t4, 0(t6)
addi t6, t6, 1
addi t5, t5, -1
bne  t5, x0, zero_loop
# 输入端口地址与回退槽也由闸钉死：a1 = 0xF0000004，a2 = 0
li   a1, 0xF0000004
li   a2, 0

# 任务从这里开始：一条语句一条语句地扫下去
```

**提示**：`t3` 当"当前字符"，`t4` 当临时用；每条语句的处理流程都是"读关键字 → 读名字 → 吃掉 `;` → 查/记账本 → 回到循环开头"。报错的字符串可以直接放在 `.data` 段里用 `la` 取地址（像 `ERR:dup:` 这种）。

> ⚠️ 一处非常隐蔽的顺序问题：报错时要印的是**名字**，但"吃掉 `;`"这一步已经把当前字符换成分号了。所以在读到一个名字之后，**先把它搬到别的寄存器**（别用会被辅助函数冲掉的临时寄存器），再往下吃 `;`、查账本；否则账本查得再对，印出来的也是 `ERR:undecl:;`。
