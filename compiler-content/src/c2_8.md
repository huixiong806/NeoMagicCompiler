## 2.8 墙上那串会分叉的数

最底层的厅里没有井，只有一面墙。

墙上刻着一串数，从左边开始：`0 1 1 2 3 5 8 13 21 ……` 一直延伸到光照不到的地方。每个数下面都画着两条细线，分别连向它前面两个数。

岩舟盯着看了半天：“每个数都是前面两个加起来。”

“对。这就是**斐波那契**。”星泠说，“这个厅的门要第 20 个数，而你手上只有这套刻痕。”

“那还不简单，写个循环，从 0 和 1 往上推。”

“可以，而且更省魔力。”星泠点头，“但卷轴这句刻痕写的是**分叉的递归**——”

她指着那两条细线：“要算第 n 个，你得同时问第 n-1 个和第 n-2 个。**每问一次就分成两支**。算到第 20 个，会有两万多条分叉。”

屏幕亮起来：

```
本关目标：int solve(int n) 返回第 n 个斐波那契数
约定：fib(0) = 0，fib(1) = 1，fib(n) = fib(n-1) + fib(n-2)
范围：0 <= n <= 20
```

“两万多条分叉，魔力够吗？”

“够，但你要给足。”星泠调高了一档魔力上限，“这就是分叉递归的代价：写法最短，算得最笨。等以后你亲手写编译器的时候，还会再遇到这句话——**同一件事，写得简单和跑得快，常常不是一回事**。”

岩舟笑了一声：“先算出来再说。”

---

**你要写的东西**

```c
int solve(int n) { ... }
```

- `fib(0) = 0`，`fib(1) = 1`；
- 更大的 `n`：`return solve(n - 1) + solve(n - 2);`
- `0 <= n <= 20`，两个分支会把调用次数翻倍，所以 `maxInstructions` 这次给到了 500 万（正常写法远用不到，但能容许较笨的写法）。

如果你愿意，也可以改用循环（记住前两个数，从底往上推），结果完全相同——两种写法都能通过。

```riscv
{
  "level": "2-8",
  "language": "c"
}
---
// 2-8 递归进阶：返回第 n 个斐波那契数（fib(0)=0, fib(1)=1）
int solve(int n) {
    if (n <= 0) {
        return 0;
    }
    if (n == 1) {
        return 1;
    }
    return solve(n - 1) + solve(n - 2);
}
```
