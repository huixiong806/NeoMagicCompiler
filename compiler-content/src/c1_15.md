## 1.15 综合：点亮符文柱

门开的瞬间，岩舟先看到的不是路，是光。

房间尽头立着一根柱子，从地面一直顶到看不见的暗处。柱身上缠着一圈圈符文槽，槽里全是暗的——只有最底下一小段在很慢地呼吸，一明一灭。

"这根不是闸了。"星泠说，"是**符文柱**。遗迹里的采掘机关靠它蓄力。"

她指向柱子底部一块方口。方口旁边刻着一行小字：**此处吞数**。

"这次不是几个数，是一串数。"她把方板贴上去，方口里传出一阵很细的沙沙声，像有字符一个接一个被吸进去，"而且是一串**字符**——它只会念，不会算。第一个数是**门槛**，后面是这一趟搬进来的矿石量，念到 `0` 为止。你要自己把字符拼成数：看到 `3` 就是三，看到 `3`、`0` 连在一起就是三十。"

岩舟把手插进方口摸了摸，里面是空的。"字符从哪儿来？"

"从**输入端口**。"星泠在方板上敲出一行地址：`0xF0000004`，"看这里的数，和看记忆晶阵里的数用的是同一条指令 `lw`——读一个字符就少一个，就像把牌子从队列头抽走。"

"送出去呢？"

"送到 `0xF0000000`，那里是**显示端口**。"她把方板翻过去，背面是一小格一小格的输入口，"闸已经在注释里替我们准备好了：`li a7, 1` 让引擎知道'我要输出一个字符'，然后 `ecall` 把 a0 里的那个字符送进显示端口。要输出 `'1'`，就往 a0 里放 `49`；输出 `'0'` 就放 `48`。"

她取出一支新刻笔，在方板边缘写下这一关要做的事：

1. `addi x20, x0, 0xF0000004` —— 先把输入端口的地址固定放进 x20，后面每次读都用它；
2. 写一个小的"读一个整数"流程：跳过空格 → 处理可能的负号 → 把每一位数字拼起来（`值 = 值 * 10 + 这一位`）；
3. 先读出门槛，存进 x8，同时写一份到 `0x1004`；
4. 循环读后面的数：读到 `0` 就跳出，否则累加；
5. 循环结束后，把**总和**也写进 `0x1004`（闸要看这个数）；
6. 总和 ≥ 门槛就把 `49` 放进 a0，否则放 `48`。

```riscv
{
  "level": "1-15",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 1,
    "readonlySuffix": 1,
    "suggested": {
      "3": "li x21, 0x1004",
      "4": "jal x1, read_int",
      "5": "addi x8, x10, 0",
      "6": "sw x8, 0(x21)"
    }
  }
}
---
# 输入端口地址固定放 x20；输入是字符流（数字之间用空格隔开，可以带负号）
# 第一个数是门槛，后面是若干矿石量，读到 0 结束；读空也会读回 0
# 任务：自己把字符拼成整数，累加到 0 为止，
#       门槛写进 0x1004、总和也写进 0x1004；总和 >= 门槛 输出 '1'，否则输出 '0'
li x20, 0xF0000004
li x21, 0x1004
jal x1, read_int
addi x8, x10, 0
sw x8, 0(x21)
# ↓ 下面从这里开始写：清零总和、循环读入并累加、判断、输出
#   输出：把字符编码写进显示端口 0xF0000000（'1' 是 49，'0' 是 48）
#   读一个整数的流程写成子程序，放在最下面（read_int: 开头，x10 里带回结果）
ecall
```

调试面板是这一关最好的帮手：输入是一次性的队列，**读走的字符不会回来**。如果你不放心，就在循环里放一条 `ebreak`，停下来看队列还剩多少、总和涨到了多少。

两个容易踩的坑：

- **数字要一位一位拼**。读回来的是字符的编号（`'3'` 是 51，`'0'` 是 48），要减掉 48 才是数字本身；遇到十位数以上还得先乘 10。
- **`0` 既是"数量为零"，也是"输入结束"**。这一关的输入里，答案是 0 的矿石量会写成 `0`，读到它就该收手——不要把它加进总和。

柱子底部的光在岩舟按下"运行"的那一瞬停了一下，然后开始往上爬。符文槽一格一格被点亮，像有人在往下走的路上回头看。

光爬到一半的时候，星泠忽然伸手按住了方板。

"等一下。"她说，"这段光的颜色不对。"

（第一章完）
