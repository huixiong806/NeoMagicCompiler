## 1.13 离开主线，去别处干一趟活

走廊之后是一间圆形的石室。

石室正中有一根矮柱，柱子上刻着一个符号：一个数乘它自己。旁边还有一行小字——**平方**。

岩舟按了下柱子，没反应。他又按了一下，柱子底部的刻度亮了一小格。

"它一次只收一个数。"星泠说，"星之语里，这种东西叫**子程序**：一段可以反复被叫去干活的刻痕。以后我们要算的是几十个数的平方，而不是一个——把你刚才按出来的那一段刻痕抄十遍？"

"抄十遍能过。"

"能过，但闸后面会要一百遍。"她取出一支新刻笔，在柱子旁边画了一道从主路岔出去的线，"要**跳出去干活，再回来**。星之语给这件事两条指令："

```text
jal  x1, 标签      # 跳到标签去干活；同时把"回来的位置"记进 x1
jalr x0, 0(x1)     # 跳回 x1 里记着的那个位置
```

"注意第一条里的 x1。"星泠把刻笔停在那上面，"它不是一个特殊的格子。它就是普通寄存器，只是**约定**用它来记返回地址，所以名字叫 `ra`——return address。`jal` 干的两件事必须一起理解：它一边跳走，一边把'我正在这一行，回来时要接着这一行'写进了 x1。"

岩舟在灰上把那条岔线接回了主线。"所以回来的时候，是照着 x1 里记的位置跳回去的。"

"对。`jalr x0, 0(x1)` 就是'跳回 x1 指的地址'——这里目标写的是 `x0`：我们不需要再记什么回来的位置了。"

**岩舟在这里吃了第一次亏**：他把参数放在 x1 里就 `jal` 过去了，结果 x1 立刻被返回地址盖掉，子程序算的是"返回地址的平方"。所以规矩是：**跳之前，先把参数挪到别的寄存器**。

```riscv
{
  "level": "1-13",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 2,
    "readonlySuffix": 1,
    "suggested": { "3": "jal x1, square", "4": "addi x10, x6, 0" }
  }
}
---
# x1 里是闸给的参数（它同时也是 ra，所以要先把参数挪走）
addi x6, x1, 0
# 任务：在这里调用 square 子程序，让它把 x6 算成平方，结果放进 x10
#      （square 写在最下面，行尾的冒号是它的路标）

ecall
# ↓ 下面两行是闸钉死的收尾
square:

```

把它写成这个顺序：

1. `jal x1, square` —— 跳去干活，x1 记下回来的位置；
2. 在 `square:` 底下，用 `mul x6, x6, x6` 把参数乘它自己，结果放进 x6；
3. 用 `jalr x0, 0(x1)`（也可以直接写 `ret`）跳回来；
4. 回到主线后，用 `addi x10, x6, 0` 把结果搬进 `a0`。

这一关里 `a0` 就是 `x10`——名字不同，格子是同一个。

**如果少了第 3 步会发生什么？** 引擎从 `square:` 往下走，走到尽头也回不来，`ecall` 会被它顺手执行掉，`a0` 里留着零。闸会告诉你答案不对——这不是它刻薄，是它真的没拿到数。

柱子被按亮的刻度，一格都没灭。岩舟把手收回来，看着那些光。

"它等着我按第二下。"他说，"第二下的时候，x1 里已经不是刚才那个数了。"
