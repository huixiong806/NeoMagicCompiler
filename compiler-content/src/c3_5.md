## 3.5 括号匹配

石厅的穹顶正在自己重排。

一圈圈刻痕从墙脚往上爬，爬到顶的时候"喀"地一声落回原位，然后整个穹顶开始往下压。

岩舟把方板举过头顶："这东西要塌了！"

"它在等一个答案。"星泠的声音反而更稳了。她指着石台上刚刚张开的一道缝——缝里是一行新的刻痕，比之前那两道都长：

> **此处读括号，配平者开门。**

"括号。"岩舟看了一眼那行刻痕，"就那六个符号？"

"就那六个。"星泠说，"`(` `)` `[` `]` `{` `}`。它把这一整串符号喂给你，你要回答它：**这些括号是不是配平的**——每一个左括号都能找到自己对应的右括号，而且**嵌套不能交叉**。"

她在地上画了两个例子：

```
[({})]      → 配平
([)]        → 不配平：最里面先开的 '(' 反而后关，交叉了
```

岩舟盯着第二个例子看了两秒："这不就是**后来先走**吗……"

"**后来先走。**"星泠重复了一遍，然后笑了，"你已经把这一关最要紧的那句话说出来了。"

---

### 这一关要用的东西：栈

她把方板背面翻出来，那里画着一间小屋。

"想象一间只能从门口进出的窄屋。你往里面摞石头：第一块放地上，第二块压在第一块上，第三块压在第二块上。现在我要做饭了，问你要**最上面那块**——你只能先搬走第三块，再搬走第二块，最后才是第一块。"

她在这个小图下面写了四个字：**后进先出**。

"这就是**栈**。名字听着玄，其实只有两条规矩：**进的时候放在最上面，出的时候只能从最上面拿**。上一次第二章讲函数调用的时候你已经在用它了——那时候引擎把返回地址往栈上摞，所以内层函数先返回，外层函数后返回，跟括号一模一样。"

岩舟一拍腿："所以括号和函数调用是同一件事？"

"是同一件事。"星泠说，"这也是编译器里最重要的两件事共用一个工具的原因。"

**而后是这一关真正的技巧**：栈里不放"看到的左括号"，而是放**你期望的右括号**。

"你在做一张待办清单。"她说，"看到 `(`，就在清单最上面写一行'待会儿要来一个 `)`'；看到 `[` 就写'待 `]`'。等真的来了一个右括号，你只需要看清单最上面那一行对不对。对了就把它划掉，不对就说明这串括号是坏的。"

用栈严格来说是**内存里的一段加上一个"栈顶指针"**，星之语里没有 `push` / `pop` 这种指令——只有 `lw` / `sw`，栈要你自己做：

```asm
li   x20, 0x3000      # 栈底：从 0x3000 开始往上长（0x2000 附近留给要输出的字）
addi x21, x0, 0       # 栈顶指针：先等于栈底，表示"栈是空的"

# 压栈：先放到栈顶这一格，再把指针往上挪一格
sw   x7, 0(x20)
addi x20, x20, 4

# 弹栈：先把指针往下退一格，再从那一格取出来
addi x20, x20, -4
lw   x6, 0(x20)
```

"注意顺序。"星泠敲了敲方板，"**压栈是先存后挪，弹栈是先挪后取。**两个顺序弄反，栈就会在你没留神的时候吃掉旁边格子里的数。"

（引擎的 `sp` 是从顶上往下长的系统栈，这一关我们不用它——自己起一个从下往上长的栈更好看清楚"指针"这两个字是什么意思。）

---

**现在必须解决的麻烦**：穹顶正在往下压，而这一关的判断标准有**三条**，缺一条都不算开门。

1. 每个左括号都找到了自己的右括号（**收工时栈必须正好空着**）；
2. 每个右括号出现时，栈顶写的那一行必须正好是它（**种类要对**）；
3. 嵌套不能交叉——这一条不用你额外写代码，前两条已经保证了它。

骨架代码已经能把输入读进来、跳过不是括号的字符了，但它不会压栈，也不会判断。你要补上：

- 输入端口 `0xF0000004`，读回 `0` 表示结束；
- 六种括号的编码：`(` 40、`)` 41、`[` 91、`]` 93、`{` 123、`}` 125；
- 用 `x18` 记"现在是否还正常"（1 = 正常，0 = 已经坏了）；
- 数完把结果写进 `0x2000`：`1` 表示配平、`0` 表示不配平；
- 输出 `ok` 或 `bad`（骨架末尾已经准备好两段字，`ok` 在 `0x2010`、`bad` 在 `0x2018`，都用一个 0 收尾，可以照着 `lb` + `a7 = 1` 逐个字符送出去）。

```riscv
{
  "level": "3-5",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 3,
    "readonlySuffix": 2,
    "suggested": {
      "1": "li x1, 0xF0000004",
      "11": "先把六种括号的编码比一遍，认出左括号和右括号"
    },
    "highlight": [13]
  }
}
---
li x20, 0x3000
li x19, 0x3000
addi x18, x0, 1
li x1, 0xF0000004
bracket_loop:
lw x5, 0(x1)
beq x5, x0, brackets_end
# ↓ 下面从这里开始写：认出六种括号，左括号压栈、右括号弹栈对比
j bracket_loop
brackets_end:
# 把结果写进 0x2000（配平 = 1，不配平 = 0），再逐字符输出 ok（0x2010）或 bad（0x2018）
li x10, 0
li x11, 0
ecall
```

三个容易踩的坑：

- **压栈和弹栈的顺序**：先存后挪、先挪后取。反过来写，第一次弹栈就会读到空栈下面的垃圾数据，判定会告诉你某个本来配平的串被判成了 bad。
- **右括号来的时候要先看栈是不是空的**。空栈还去弹，就会读到不存在的"期望值"——用 `beq x20, x19, 坏掉了` 先挡一下，`x19` 存着栈底 `0x3000`。
- **别忘了收尾那一问**：输入读完了，如果栈里还留着东西（比如只有一个 `(`），说明有左括号没人配——这一条和"中途对不上"是两件不同的事，两条都要判。

穹顶在最后一个括号判完的瞬间停住了，然后从中间分开。

缝里落下一件东西，落在石台上，砸出很闷的一声。

岩舟蹲下去捡起来。是一块薄薄的、半透明的**石板**，正中间刻着一道算式——不是数，是一串**符号**：

```
1+2-3+4
```

石板上没有等号，没有答案。它只是等着。

星泠看了很久，忽然说："伊塔尔到最后还是在教同一件事。前面四关，它让我们把字符**认出来**；这一关让我们认**结构**。而这最后一块——"

她伸手把石板翻过来，背面刻着一行字：

> **认完了，就该算了。**

（下一关：只有加减）
