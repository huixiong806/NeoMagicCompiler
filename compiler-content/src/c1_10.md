## 1.10 让它自己数一遍

牌子背面那句话，岩舟读了三遍。

"要算的次数由闸给你。"他把牌子翻回来又翻过去，"闸给的是 x1。可 x1 里只有一个数——比如 100。它要什么？"

星泠已经在牌子上找接口了。她按下牌子底部的凹槽，牌子亮起一行小字：**请给出 1 到 n 的总和**。

"1 加 2 加 3，一直加到 n。"她说，"n 在 x1 里。结果放 x10。"

岩舟试着在灰上写 1+2+3+…，写到第 7 个就没地方了。"一百个数，我难道刻一百条 `add`？"

"刻一百条也能过，闸不会生气——但闸下一次给你的可能是 1000。"星泠把刻笔横过来，在灰上画了一个圈，"分支指令上一关只用来跳过一段；其实它还能**往回跳**。往回跳，就是重复。"

她在圈里画了三步：

```text
add x10, x10, x5    # 把当前的计数器加进总和
addi x5, x5, 1      # 计数器加一
blt x5, x1, 循环     # 计数器还没超过 n？跳回第一步
```

"x5 是计数器，从 1 开始；x10 是总和，从 0 开始。"她把刻笔点在圈上，"`blt x5, x1, 循环` 有一半的时间是成立的，所以读数条会一圈一圈地回到上面——这就是**循环**。它唯一停下来的条件，是'计数器不再小于 n'。"

岩舟盯着那个圈看了很久。"所以我不是刻一百条，我是刻三条，让引擎自己转一百圈。"

"而且闸下次给 1000，你也不用改一个字。"

```riscv
{
  "level": "1-10",
  "language": "asm",
  "constraints": {
    "readonlySuffix": 1,
    "suggested": { "1": "addi x10, x0, 0", "2": "addi x5, x0, 1" }
  }
}
---
# x1 里是 n，任务：把 1+2+...+n 的结果放进 x10
# x10 是总和，x5 是"现在数到几了"

# 循环体写在下面，记得在行尾加上冒号做路标

ecall
```

循环最容易错的地方是**起点**：`x5 = 1` 时，第一次加进去的是 1；如果 `x5` 从 0 开始，你会白转一圈，虽然结果一样，但那一圈是浪费的。另一个坑是**退出条件**：`blt x5, x1, 循环` 里，x1 是"要加到几"，不是"要转几圈"。

这一关的测例会给你 `n = 0`。**`n = 0` 意味着一次都不加，x10 是 0**——循环得能自己走开，不能卡住。

牌子上的数字跳了一下：`100`，然后归零，重新跳。岩舟往房间深处看了一眼。

"下一个房间的格子，不在这根柱子上了吧。"

"不在。"星泠说，"下一排数住在墙里。而这一次，闸不会只给你一个数——它会给你一整排。"
