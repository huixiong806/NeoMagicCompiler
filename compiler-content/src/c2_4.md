## 2.4 一整排感应石

深井底下是一间长条形的厅。地面嵌着一排感应石，一块挨着一块，各自的读数都不一样——有些是正的，有几块是负的（越靠近井口，读数越冷）。

厅门上刻着一句话：

```
找出读数最大的那块石头，站在它上面，门就开了。
```

“就这么简单？”岩舟已经迈出一步。

“等等。”星泠蹲在第一块石头边上，“门要的是**哪一块**，不是多大。而且——”她扫了一眼整排石头，“读数会重复。两块一样大的时候，门只认**更靠前**的那一块。”

岩舟沉默了一下：“……所以不能随便挑一块。”

“对。卷轴第四句刻痕讲的是这个。”星泠指着卷轴，“古人不再一块一块给石头起名字。他把整排石头看成一件事：**一排数字**，用位置来区分——第 0 块、第 1 块、第 2 块。位置从 0 开始，这是遗迹里所有带序号的东西的习惯。”

屏幕上跳出新的目标：

```
本关目标：int solve(int* a, int n)
  a 是一排感应石的起始地址，n 是石头的块数
  返回读数最大的那块石头的下标（从 0 起算）
  若有多块并列最大，返回最小的下标
```

“**a 是地址**，”星泠强调了一遍，“魔导引擎传给你的不是一整排数，而是第一块石头的门牌号。你用 `a[0]`、`a[1]`……就能取到后面每一块；星咒里 `a[i]` 和 `*(a + i)` 完全等价。”

岩舟已经开始敲键盘了：“那我先把第 0 块当成最大的，再一块一块比。”

---

**你要写的东西**

```c
int solve(int* a, int n) { ... }
```

- `a`：数组的**起始地址**（第一块石头的地址）。用 `a[i]` 或 `*(a + i)` 访问第 `i` 个元素。
- `n`：元素个数（至少 1 个，不会传 0）。
- 返回**最大元素的下标**；并列最大时返回**最小**的下标。

技巧：先假设下标 `0` 最大，用变量 `best` 记住它，然后从 `1` 开始逐个比较。只有在遇到**严格更大**的元素时才更新 `best`，这样并列时会自然保留最靠前的下标。

本关测试会把数组预先放进**记忆晶阵**里，参数传的是它的地址（测试里用十进制数字写，比如 `8192` 就是 `0x2000`）。数组里可能有负数，别写成"无条件替换成当前元素"。

```riscv
{
  "level": "2-4",
  "language": "c"
}
---
// 2-4 数组与下标：返回最大值所在的下标（并列取最小下标）
int solve(int* a, int n) {
    int best = 0;
    int i = 1;
    while (i < n) {
        if (a[i] > a[best]) {
            best = i;
        }
        i = i + 1;
    }
    return best;
}
```
