## 1.11 一排格子里的算术

下一个房间是条窄长的走廊，两侧墙面上各钉着一排刻度。

第一排刻度从 `0x1000` 起，一个挨一个，每个格子里面都睡着数字。岩舟数了数，数到一半就放弃了。

"太多了。"他说，"上一关的循环是 1、2、3 一直数上去；现在这些数各自不一样，有大有小。"

"那是因为上一关的数在寄存器里，这关的数在**记忆晶阵**里。"星泠把手放在第一排刻度的起点，"x1 里是闸给的 n——这一排里前 n 个格子要加在一起。结果照样放 x10。"

"格子怎么一个个走？"

"上一关你数的是'数到几了'，这一关你要数两个东西：**数到第几个**，和**现在站在哪一格**。"

星泠用刻笔在第二排刻度上敲了两下：

```text
lw   x7, 0(x6)     # 读出 x6 指着的那一格
add  x10, x10, x7  # 加进总和
addi x6, x6, 4     # 指针往后挪一格（一个字是 4 个字节）
addi x5, x5, 1     # 计数加一
```

"x6 是**指针**：它里面装的不是数据，是地址。`0(x6)` 表示'x6 指着的那一格'。"她顿了一下，"每次加 4，指针就往后挪一格——这是这一关最容易写错的地方。**写在里面的数加多少，取决于你想挪几格，而一格是 4 个字节，不是 1。**"

"加错会怎么样？"

"你会读到别的格子，甚至是两个数中间那一半——闸会告诉你它不满意。"

```riscv
{
  "level": "1-11",
  "language": "asm",
  "constraints": {
    "readonlyPrefix": 1,
    "readonlySuffix": 1,
    "suggested": { "2": "addi x10, x0, 0", "3": "addi x5, x0, 1" }
  }
}
---
li x6, 0x1000
# x1 里是 n，x6 已经指着第一排刻度的起点 0x1000
# 任务：把前 n 个格子里的数加起来，结果放进 x10

# 循环体写在下面（记得在行尾加上冒号做路标）

ecall
```

走路的时候想想每一步：**先读、再加、最后挪**——顺序不能换。如果先挪指针，读到的就是下一格，第一个数会被漏掉；如果忙着挪指针忘了加，总和会少一格。

走廊尽头的门开了一条缝，里面很黑。星泠把方板举起来当灯，光只照到地面上一小圈。

"这里的门认的是'过程'，不只是'结果'。"她说，"进去之后，我们得让引擎**停下来**，好让岩舟看清它到底在做什么。"
